# 云平台 镜像 与 云盘 产品语义

> 前置：[[concepts/KVM 公有云 镜像 适配]]（规范与磁盘形态）、[[concepts/QEMU 设备模型 与 virtio 协议]]（设备侧）。
> 应用：[[entities/公有云镜像 制作 与 导入 实战]] §3（导入参数）、[[concepts/FinOps 与云资源优化]]（成本与选型）。

## 1. 为什么"产品语义"也属于基础知识

同样一块 100 GiB 的盘、同样一个"镜像"，在不同云上的**行为约束**不同：
能不能在线扩容、扩容后要不要手动扩分区、能不能缩容、镜像要不要声明启动模式、导进去能不能跨地域用……
这些不是"技术细节"，而是**平台的产品契约**。踩坑往往不是不懂 Linux，而是不知道契约边界在哪。

## 2. 实例规格族与代际

### 2.1 命名与维度

| 维度 | 取值示例 | 影响 |
|---|---|---|
| 家族 | g（通用）、c（计算）、r（内存）、i（本地盘）、ebm（裸金属） | 资源配比 |
| 代际 | g6 → g7 → g8i → g9i | **CPU 平台、存储协议、固件要求**都可能变 |
| 后缀 | a = AMD、y = 倚天（Arm）、i = Intel、se = 本地 SSD | 架构与本地盘 |
| 架构 | x86_64 / aarch64 | **镜像架构必须匹配** |

> 代际是"隐形的镜像门槛"：新代际往往要求 UEFI、改用 NVMe 协议云盘，
> 老镜像不做改造就"选不到"或"起不来"。这正是 [[concepts/KVM 公有云 镜像 适配]] §1 那张表的由来。

### 2.2 三代际差异对镜像的连带影响

```
新代际 → 要求 UEFI 引导      → 镜像必须有 ESP + fallback
       → 云盘改 NVMe 协议    → 镜像 initramfs 必须有 nvme 驱动
       → 平台支持 UEFI-Preferred → 双引导镜像可通吃
```

## 3. 云盘类型与性能档

> 以下为**典型档位示例**，具体名称/参数以各家当日文档为准；理解重点是"档位决定 IOPS/吞吐上限，
> 而协议（virtio/NVMe）决定 guest 侧访问方式"。

| 类别 | 典型档位 | 协议 | 特点 |
|---|---|---|---|
| 增强型 SSD（阿里 ESSD） | PL0 / PL1 / PL2 / PL3 | virtio 或 **NVMe**（视规格） | IOPS 与吞吐按档位线性提升，PL3 可达数十万 IOPS |
| 通用 SSD 型 | — | virtio | 性价比主力 |
| 高效/普通云盘 | — | virtio | 低端，延迟高 |
| 本地盘（NVMe SSD） | — | 直挂/本地 | 延迟最低，但**无冗余、实例释放即丢、不能做镜像系统盘** |

**两个常见误解**：
1. "云盘 IOPS 上限就是我能拿到的 IOPS"——实际还受**实例规格的存储带宽上限**约束（规格卡脖子）
2. "NVMe 协议云盘 = 本地 NVMe 盘"——前者是网络/分布式块存储的协议呈现，后者是物理本地盘

## 4. 系统盘与数据盘

| 维度 | 系统盘 | 数据盘 |
|---|---|---|
| 内容 | 镜像展开 | 业务数据，通常手动初始化（分区+格式化+挂载） |
| 与镜像关系 | 镜像决定初始内容 | **不随镜像走**（这是 fstab 要 `nofail` 的原因） |
| 常见创建语义 | 容量可大于镜像（平台自动扩到指定容量，需 guest 侧 growpart） | 需显式挂载、写 fstab |
| 生命周期 | 随实例释放（可选保留） | 独立于实例（可卸载/挂载到别的实例） |

**关键契约**：创建实例时把系统盘选成 100 GiB，**不等于** guest 里根分区就是 100 GiB ——
分区表还是镜像里的布局，需要 growpart/resizefs（cloud-init 通常自动做，见 [[concepts/磁盘分区 文件系统 与 挂载管理]] §4）。

## 5. 自定义镜像生命周期

```
制作来源                        属性声明                     流转                   退役
───────────────        ─────────────────────        ────────────────      ──────────
① 导入（OSS/OBS/COS）    架构 x86_64/aarch64           跨地域复制           删除
② 从实例创建             启动模式 BIOS/UEFI/UEFI-Preferred  跨账号共享         （快照保留）
③ 从快照创建             NVMe 驱动 支持/不支持          加密
④ 从其他镜像复制         License 类型                  创建实例测试
```

### 5.1 导入参数为什么这么多（每个都有事故对应）

| 参数 | 填错的后果 |
|---|---|
| 架构 | 架构不符 → 该镜像在目标规格族不可选 |
| 启动模式 | 与镜像实际不符 → 实例起不来（腾讯云文档明确提示） |
| NVMe 驱动 | 未声明"支持" → 新代规格创建时选不到该镜像 |
| License 类型 | 合规问题（RHEL 等商业发行版订阅） |
| 磁盘设备类型（华为云） | UEFI 镜像必须选 scsi，否则不可用 |

### 5.2 跨云不可平移

自定义镜像**不能**在云之间直接复制/迁移 —— 各家的格式、分区要求、驱动要求不同，
必须"各自导出 → 各自导入"（三家差异见 [[concepts/KVM 公有云 镜像 适配]] §3）。
跨云搬运的替代方案是**迁移工具**（SMC/SMS 类，见该页 §14）。

## 6. 快照 / 镜像 / 备份：语义边界

| 对象 | 是什么 | 能启动实例？ | 用途 |
|---|---|---|---|
| **快照** | 某块云盘在某时刻的数据状态 | 需先做成镜像或挂成盘 | 数据回滚、备份基座 |
| **镜像** | 可启动模板（含分区表/引导/文件系统） | 能 | 批量创建实例 |
| **备份** | 带保留策略的数据副本（通常是服务化的） | 一般不能直接启动 | 长期容灾、合规 |

> 常见误解："我做了快照就等于有镜像"。快照是**盘**的维度，镜像是**可引导系统**的维度。

## 8. 选型与成本的思考框架（接 FinOps）

| 决策点 | 权衡 |
|---|---|
| 规格代际 | 新代际性能/功能更好，但要求镜像改造（UEFI/NVMe 驱动） |
| 云盘档位 | IOPS 需求 vs 成本；注意规格的存储带宽上限 |
| 系统盘容量 | 扩容容易（growpart），但缩容难 → 别一次买太大 |
| 本地盘 vs 云盘 | 极致延迟 vs 可迁移性/冗余 |
| 自制镜像 vs 迁移工具 | 长期批量 vs 一次性搬运 |
