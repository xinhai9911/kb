# 存储、备份与归档策略

## 概述

数据是视频制作的命脉。丢失一个小时的拍摄素材可能意味着数十万人民币的损失。一套完整的存储策略覆盖**三个层次**：现场存储（摄取）、工作存储（编辑）、长期存储（归档）。每个层次有不同的速度、容量、可靠性要求。

## 拍摄素材存储层次

典型的视频制作数据流按"热的（Hot）→ 温的（Warm）→ 冷的（Cold）"分层：

```
拍摄现场                     工作阶段                      归档阶段
┌─────────────┐          ┌──────────────┐             ┌──────────────┐
│ 原始素材     │  ───→   │ 工作盘       │   ───→      │ 长期归档      │
│ SSD/CFast    │  拷贝   │ RAID 5/6     │   定剪后     │ LTO / HDD    │
│ (Hot)        │         │ (Warm)       │             │ (Cold)       │
└─────────────┘          └──────────────┘             └──────────────┘
                               │
                               ↓
                         备份盘
                         RAID 1/10
                         (备份)
```

### 第一层：现场存储（Hot）

- **DIT 工作流程**：每天拍摄结束后，DIT（数字影像技师）将摄影机存储卡（CFexpress 2.0 / SxS Pro / RED Mini-Mag / SSD）中的素材拷贝至现场硬盘。
- **最小三副本原则**：现场至少保留三份——原始卡（不格式化直到下一张卡成功校验）、现场 RAID（主工作盘）、现场备份盘（第二套物理驱动器）。
- **读卡速度**：CFexpress 2.0 典型读速 ~1200 MB/s；SxS Pro V ~1000 MB/s。需要相应的读卡器和 USB 3.2 Gen 2x2 / Thunderbolt 3 接口。

### 第二层：工作存储（Warm）

- **剪辑工作盘**：编辑中期素材存放位置——转码后的代理文件（如有）、项目文件、缓存、预渲染。
- **性能要求**：能够流畅播放至少 4 轨高码率 ProRes 422 HQ 或 DNxHR HQ（合计约 800-1200 Mbps）。
- **推荐配置**：
  - 单机剪辑：USB 4 / Thunderbolt 3+ 外置 SSD（Samsung T7 / LaCie Rugged）。仅适用于单轨低码率代理。
  - 专业剪辑：RAID 5 或 RAID 6 阵列，通过 10GbE / Thunderbolt 连接。推荐 Promise Pegasus / OWC ThunderBay 或 QNAP / Synology NAS。
  - 多人协作：共享存储（Avid Nexis / EditShare / QNAP TVS-h 系列）通过 10/25 GbE 或 Fibre Channel 连接。

### 第三层：归档（Cold）

见下方"归档媒介对比"一节。

## RAID 类型与选择

| RAID 级别 | 最少盘数 | 容错 | 可用容量 | 读取性能 | 写入性能 | 适用场景 |
|-----------|---------|------|---------|---------|---------|---------|
| **RAID 0** | 2 | 无 | 100% | 极优 | 极优 | 临时缓存/速度测试（不推荐存储唯一数据） |
| **RAID 1** | 2 | 1 盘 | 50% | 读优写一 | 一般 | 系统盘、操作系统、应用 |
| **RAID 5** | 3 | 1 盘 | (n-1)/n | 优 | 一般 | 通用剪辑存储。单盘容错，性价比高 |
| **RAID 6** | 4 | 2 盘 | (n-2)/n | 优 | 一般 | 大容量归档。双盘冗余，重建时间长 |
| **RAID 10** | 4 | 每组 1 盘 | 50% | 极优 | 极优 | 高 IOPS 场景（多机位、VFX 缓存）。最佳性能和保护 |

**剪辑专用建议**：
- 4K/8K 单机剪辑：RAID 5（HDD 4-8 盘）或 RAID 0（NVMe SSD 2 盘，但务必频繁备份）。
- 多用户同时访问：RAID 6（HDD 8-12 盘）或 RAID 10（SSD 4 盘）。
- **重建风险**：RAID 5 的大容量 HDD（16TB+）重建时间可达 20-40 小时，此间第二盘故障概率增加。16TB+ 阵列推荐 RAID 6。

## 归档媒介对比

| 媒介 | 单盘容量 | 读取速度 | 寿命 | 单 GB 成本 | 优点 | 缺点 |
|------|---------|---------|------|-----------|------|------|
| **LTO-8/9**（磁带） | 12TB/18TB | ~300 MB/s | 30 年 | ~$0.01 | 最可靠的长期归档、低功耗 | 需要专用驱动器（~$3000+）、线性访问 |
| **HDD**（外置硬盘） | 4-22TB | ~150 MB/s | 3-5 年 | ~$0.015 | 便宜、随机访问、即插即用 | 机械故障、工作温度敏感 |
| **SSD** | 1-8TB | >1000 MB/s | 5-10 年 | ~$0.05+ | 快、抗震、安静 | 写入寿命有限（NAND 磨损）、贵 |
| **云存储**（S3/Glacier） | 无限 | 依网络 | 持久 | ~$0.004/月（Glacier） | 异地灾备、按需扩容 | 长期费用累积、恢复速度慢（Glacier 需 12h+） |
| **M-Disc**（蓝光） | 100GB | ~5x BD-R | 1000 年（标称） | ~$0.03 | 理论上极长寿命 | 容量极小、速度慢 |
| **NAS** | 依配置 | 依网络 | 5-10 年 | 较高 | 网络可访问、可扩展 | 需要维护 |

**LTO 磁带归档流程**：
1. 项目完成定剪后收集所有最终素材
2. 使用 LTFS（Linear Tape File System）格式化磁带
3. 使用归档软件（Archivematica / YoYotta / Hedge）写入
4. 校验写入完整性
5. 两张磁带（主 + 副本），两张分开存放
6. 标记：项目名称、日期、目录内容、校验码

## 数据完整性

数据拷贝不等于数据安全——静默损坏（Bit Rot）是真实存在的风险。

- **Checksum（校验码）**：拷贝文件时同时计算 MD5 / SHA-256 / xxHash。复制完成后比对源文件和目标文件的校验码，确认完全一致。
- **校验工具**：DaVinci Resolve Clone Tool（+ 校验）、Hedge / ShotPut Pro（强制校验，不一致则报警）、TeraCopy / FastCopy（+ 校验选项）。
- **Verify after Copy**：坚持"Copy + Verify"而非"Copy Only"。
- **Bit Rot 检测**：归档后的数据需定期完整性扫描——ZFS / Btrfs（写时复制文件系统）内置 Block Checksum，自动检测和修复静默损坏。建议归档卷使用 ZFS。
- **3-2-1 备份法则**：3 份副本、2 种不同媒介、1 份异地（offsite）。

## 项目归档最佳实践

### 归档前准备

- **媒体离线（Media Offline）**：归档前确保所有源素材都已链接。Premiere 中"Consolidate and Transcode"；Resolve "Relink clips"解链后收集。
- **清理**：删除不需要的垃圾素材（NG takes、空镜头、缓存文件），可减少归档数据量 30-50%。
- **舍取策略**：归档什么？
  - **必须归档**：最终母版（ProRes 4444 / DNxHR 444）、最终混音母版、项目文件（.prproj / .drp / .fcpxml）、主要源素材。
  - **可选归档**：代理文件、渲染缓存、中间版本。如空间允许保留，否则可放弃。
  - **不归档**：Media Cache 文件、Auto-Saves（保留最近几版即可）、操作系统临时文件。

### 项目打包

- **Premiere**：Project Manager → Collect Files and Copy to New Location → 勾选"Include Preview Files"（可选）。
- **Resolve**：File → Project Manager → Right-click → Export Project Archive (.drp)。注意这**不包含媒体文件**——需额外 Project Manager → Consolidate Transcodes 或手动收集媒体。
- **FCP**：File → Export Package → 选择"Copy Media to Package"。导出为 .fcppkg 并在目标位置打开。

### 元数据保存

- 使用 **Spreadsheet / Asset Manager** 记录每盒磁带/每个 S3 Bucket 的内容清单。
- 清单应包含：项目名称、日期、参与人员、内容目录、总大小、校验码值、归档存放位置、归档有效期。
