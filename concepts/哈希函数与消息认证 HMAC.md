# 哈希函数与消息认证：HMAC

> 入口 [[concepts/加密算法总览与分类]]。本文聚焦完整性保障——哈希与 MAC。

## 1. 密码学哈希的性质

哈希把任意长输入映射为定长摘要，安全哈希需满足：

| 性质 | 含义 | 被破坏的后果 |
|------|------|-------------|
| **抗原像** (Preimage) | 给摘要难反推原文 | 摘要泄露原文 |
| **抗第二原像** | 给 m 难找 m'≠m 同摘要 | 伪造不同内容同摘要 |
| **抗碰撞** (Collision) | 难找任意 m≠m' 同摘要 | 可构造冲突证书/签名 |

> [!note] 抗碰撞 vs 抗原像的强度差异
> 抗碰撞比抗原像**更弱**——碰撞攻击复杂度约 O(2^(n/2))，而原像 O(2^n)。所以 256-bit 哈希的抗碰撞强度约 128 bit。

## 2. 主流哈希算法

| 算法 | 输出 | 状态 | 用途 |
|------|------|------|------|
| MD5 | 128 bit | **已破，禁用** | 仅老系统兼容/非安全校验 |
| SHA-1 | 160 bit | **已破（2017 实际碰撞）** | 禁用，证书已淘汰 |
| **SHA-256 / SHA-512** | 256/512 bit | 主流 | TLS 指纹、证书、签名 |
| **SHA-3 (Keccak)** | 可配置 | NIST 备选 | 与 SHA-2 结构不同，抗同类型攻击 |
| **SM3** | 256 bit | 国密 | 国内合规（见 [[entities/国密 SM2_SM3_SM4 实战]]） |
| BLAKE2 / BLAKE3 | 可配置 | 现代、极快 | 文件校验、高性能场景 |

- TLS 1.3 使用 **SHA-256 / SHA-384** 作为握手/证书的哈希与 HKDF 基础。
- **SHA-1 在所有安全场景已退役**；浏览器对 SHA-1 证书报错。

## 3. HMAC：带密钥的哈希（消息认证码）

哈希本身**不认证**——任何人都能算。需要**密钥**才能生成/验证，这就是 MAC。

HMAC 结构（避免「哈希密钥拼接」的缺陷）：

```
HMAC(K, m) = H( (K' ⊕ opad) || H( (K' ⊕ ipad) || m ) )
```

- 嵌套两次哈希 + 内外 pad，即使底层哈希有某些弱点也能保持安全（Mihir Bellare 证明）。
- 密钥 K 被规范化为块长 K'；opad/ipad 是固定常量。
- **HMAC 不提供非对称认证/不可否认**——验证方必须持有同一密钥（双方共享密钥），适合对称场景（如 AES-GCM 的 AAD、API 请求签名）。

### 3.1 MAC vs 签名

| | MAC (HMAC) | 数字签名 (ECDSA) |
|---|---|---|
| 密钥 | 双方共享对称密钥 | 公钥/私钥对 |
| 不可否认 | ✗（对方也能生成） | ✓ |
| 速度 | 极快 | 慢 |
| 用途 | 对称通信完整性、API 鉴权 | 证书、软件签名、身份 |

## 4. 哈希在加密系统里的位置

```
TLS 握手：
  - Transcript Hash：把之前所有握手消息哈希，用于派生密钥与 Finished 验证
  - 证书签名：CA 用 Hash(证书) 签名
  - HKDF：基于哈希的密钥派生函数，从共享秘密扩展出多把密钥
  - AEAD 标签：GCM 的 GHASH / ChaCha20 的 Poly1305 本质是带密钥的 MAC
```

- **HKDF**（RFC 5869）：`HKDF-Expand(HKDF-Extract(salt, secret), info, len)` —— 把 ECDHE 共享秘密变成多把独立密钥（客户端写密钥、服务端写密钥、IV 等）。现代密钥管理基石。
- **AEAD 的认证标签**本质就是 MAC，保证密文未被篡改。

## 5. 常见陷阱

| 陷阱 | 后果 | 正确做法 |
|------|------|---------|
| 用 MD5/SHA-1 做安全摘要 | 可被碰撞伪造 | SHA-256 起 |
| 把哈希当 MAC 用 | 任何人可伪造 | 用 HMAC/带密钥结构 |
| 自己设计 MAC 结构 | 容易被长度扩展攻击 | 用 HMAC/标准 AEAD |
| 密钥复用为多个用途 | 跨协议重放 | 用 HKDF + 不同 info 派生 |

## 6. 性能视角

- SHA-256 软件约 0.5–2 GB/s；SHA-NI（`SHAEXT`）可再翻倍。
- BLAKE3 多核并行可达数十 GB/s，适合大文件完整性校验。
- HMAC 成本 ≈ 2 次哈希，TLS 中占比小，但批量数据时 AEAD 的 MAC 是主要开销之一（见 [[concepts/加密硬件加速 AES-NI与协处理器]]）。
