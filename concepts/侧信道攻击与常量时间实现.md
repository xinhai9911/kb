# 侧信道攻击与常量时间实现

> 入口 [[concepts/加密算法总览与分类]] §6。加密**正确性**不等于**安全**——实现泄露会击穿算法。

## 1. 什么是侧信道

密码算法在数学上安全，但**物理/时序实现**会泄露密钥相关信息：

| 侧信道 | 泄露量 | 典型攻击 |
|--------|--------|---------|
| **时序** (Timing) | 执行时间随密钥/数据变化 |  RSA 模幂、AES T-table |
| **缓存** (Cache) | 访存模式 | Flush+Reload、Prime+Probe、Spectre |
| **功耗/电磁** | 运算功耗曲线 | DPA（差分功耗分析），针对智能卡/HSM |
| **故障注入** | 错误结果 | 改变电压/时钟诱导错误，反推密钥 |

威胁模型：攻击者与受害者在**同一物理机/同一 CPU**（云多租户、浏览器 JS、同进程）时，时序+缓存攻击尤其现实。

## 2. 经典案例

### 2.1 RSA 时序攻击（Kocher 1996）

RSA 解密用中国余数定理加速时，若某分支早返回（错误检测），执行时间暴露哪部分算错 → 逐步恢复私钥。对策：盲化（blinding）+ 常量时间模幂。

### 2.2 AES T-table 漏洞

软件 AES 常用**查表（T-table）**加速：`state ^= T[byte]`。查表下标是密钥相关明文 → 缓存访问模式泄露密钥字节。这是为什么纯软件 AES 既慢又易被缓存攻击。

- **对策 A**：用 AES-NI 硬件指令，S-box 在寄存器内完成，无数据相关查表（见 [[concepts/加密硬件加速 AES-NI与协处理器]]）。
- **对策 B**：bitsliced / 无查表软件实现（慢但常量时间）。

### 2.3 Lucky13 / Lucky Microseconds

TLS 的 CBC MAC 检查在**出错时走不同代码路径/时间**，攻击者可测时序差异逐字节恢复明文。对策：常量时间比较 + AEAD 取代 CBC。

### 2.4 Spectre / Meltdown

乱序执行 + 推测执行会把「本不该访问」的内存读进缓存，再用缓存侧信道读出。影响跨进程密钥泄露。对策：序列化指令（`LFENCE`）、限制推测、KPTI。

## 3. 常量时间编程原则

**核心：任何依赖 secret 的分支、内存访问、循环次数都必须消除。**

```c
// ✗ 数据依赖分支（泄露 secret）
if (secret_bit) { x = a; } else { x = b; }

// ✓ 无条件计算两种结果再选（时间恒定）
uint32_t mask = secret_bit - 1;        // 全 0 或全 1
x = (a & ~mask) | (b & mask);

// ✗ 数据依赖查表
t = T[secret_byte];

// ✓ 用 AES 指令或 bitsliced 无查表

// ✗ 非常量时间比较（可被计时区分首个不同字节）
for (i=0; i<len; i++) if (a[i]!=b[i]) return 0;

// ✓ 累加异或，最终比较
diff = 0;
for (i=0; i<len; i++) diff |= a[i] ^ b[i];
return diff == 0;
```

### 3.1 工程清单

- 无 `if (secret)` / `switch (secret)` / 数组下标依赖 secret。
- 循环次数不依赖 secret（如「处理到第一个 0 字节」会泄露长度）。
- 不用 `memcmp` 比较 MAC/标签（用 `CRYPTO_memcmp`）。
- 避免 secret 进缓存热点路径；能用硬件指令（AES-NI）就别软件查表。

## 4. 库的防护现状

| 库 | 防护 |
|----|------|
| **BoringSSL** (Google) | 默认常量时间，去 T-table，强审计 |
| **OpenSSL** | 现代版本多数路径常量时间，但历史坑多（见 [[entities/OpenSSL_BoringSSL 开发集成实战]]） |
| **libsodium** | API 设计即防误用，默认安全 |
| **Trezor/HSM** | 物理侧信道防护（屏蔽、随机延迟） |

> 开发者不要自己实现密码原语——用经过审计的库，且用其**常量时间 API**（如 `CRYPTO_memcmp`、`EVP` 高层接口而非底层块函数）。

## 5. 性能代价

常量时间代码牺牲分支预测与查表加速，通常慢 10–30%。但相比侧信道泄露，这是必要代价。AES-NI 让常量时间 AES 反而比软件 T-table **更快更安全**，是双重赢。
