# 镜像 资产 治理 与 成本

> 前置：[[concepts/云平台 镜像 与 云盘 产品语义]]（镜像生命周期与规格语义）、[[entities/镜像 构建 流水线]]（产线）。
> 相关成本框架：[[concepts/FinOps 与云资源优化]]。

## 1. 为什么要治理：镜像失控的三种典型后果

| 后果 | 场景 |
|---|---|
| **不知道哪台实例用的哪个镜像** | 出安全事件要评估影响面，只能一台台看 |
| **误删在使用的镜像** | 删除后无法再扩缩容/重建；快照与镜像的依赖关系也断 |
| **版本不可复现** | "同版本"镜像内容不同，问题无法回归 |

治理的目标就一句话：**任何一台实例都能回答"我来自哪个镜像、那个镜像是怎么来的"**。

## 2. 命名与版本规范

推荐把"可追溯"编码进名字里：

```
appliance-<产品>-<版本>-<架构>-<代际/用途>-<构建号>-<git短哈希>.qcow2
例：appliance-nsg-2.3.0-x86_64-uefi-20261016.3-a1b2c3d.qcow2
```

| 字段 | 为什么必须有 |
|---|---|
| 产品/版本 | 业务语义 |
| **架构** | x86_64 / aarch64，架构不符根本不可用 |
| 用途/代际 | 是否需要 NVMe 驱动、是否双引导 |
| 构建号 + git 短哈希 | 回到源码与构建日志 |
| 后缀与校验 | `.qcow2` + 同名 `.sha256`，上传前校验 |

> 反模式：`appliance-final.qcow2`、`appliance-new2.qcow2`、"最终版真的最终.qcow2"。

## 3. 镜像族系（image family）与"最新可用"

主流云支持把多个镜像挂到**同一族系**下，创建实例时选族系即"取该族系最新可用版本"：

| 好处 | 风险 |
|---|---|
| 扩容/重建实例自动用最新镜像，不必改模板 | **不锁版本**时会静默拿到新镜像 → 变更有"隐形发布"效应 |

**实践建议**：
- 长期运行/生产扩容用**族系**（省运维）
- 需要严格可复现（合规/回归）用**具体镜像 ID 锁定**
- 族系的"最新"变更要**走发布流程**并通知，别让扩容变成未公告的上线

## 4. 台账：镜像 ↔ 实例的双向映射

| 记录项 | 用途 |
|---|---|
| 镜像 ID / 名称 / 族系 / 状态 | 资产管理主体 |
| **创建时间 / 创建人 / 来源**（导入 or 实例快照 or 复制） | 审计与追溯 |
| sha256 + 构建号 + git commit | 与流水线对齐 |
| 组件清单（关键包版本） | CVE 影响面评估 |
| **使用方**：哪些实例/规格/地域在用 | 删除前检查、影响面评估 |
| 目标云 + 启动模式 + NVMe 驱动属性 | 与交付物一致 |

```bash
# 阿里云：查镜像与实例的关联（示例思路）
aliyun ecs DescribeImages --ImageId <id>
aliyun ecs DescribeInstances --ImageId <id> --RegionId cn-hangzhou
# 腾讯/华为：对应 DescribeImages / 查询实例 API
```

> 私有云侧可查：`openstack image list`、`openstack server list --image <id>`。

## 5. 共享、复制与加密

| 动作 | 说明 | 注意 |
|---|---|---|
| 跨账号共享 | 把镜像共享给其他账号使用 | 共享后**对端删除/变更不可控**；敏感镜像慎共享 |
| 跨地域复制 | 云内复制到另一地域 | 有费用与时间成本；**按需复制**而非全量铺开 |
| 加密 | 镜像可加密 | 加密后跨账号共享/复制的兼容性要验证；密钥管理独立治理 |
| **跨云** | **不能直接复制** | 必须各自导出/导入（见 [[concepts/KVM 公有云 镜像 适配]] §3） |

## 6. 生命周期与配额

| 策略 | 做法 |
|---|---|
| 保留策略 | 只保留最近 N 个版本 + 每季度保留一个基线版 |
| 防误删 | 删除前查台账"是否仍被实例使用"；关键版本打标签/加锁 |
| 过期清理 | 停止维护的族系成员定时下线（**先确认无实例依赖**） |
| 配额 | 镜像数量与容量有配额；跨地域复制会快速消耗 |
| 状态处理 | 导入失败留下"不可用"镜像要清理（否则一直占配额） |

## 7. 回滚策略

| 方式 | 适用 | 代价 |
|---|---|---|
| **换镜像重建实例**（改族系/指定旧镜像 ID） | 常规发布回滚 | 需重建；数据在数据盘则影响小 |
| **快照回滚数据盘** | 数据被改坏 | 系统侧不回滚 |
| **系统盘快照恢复** | 系统配置被改坏 | 实例需停机；快照链管理复杂 |
| 不可变系统事务回滚（bootc/ostree） | 支持该范式的系统 | 需要系统侧配套（见 [[concepts/容器镜像 与 系统镜像 的边界]] §4） |

**关键**：回滚能力要在**发布前**就设计好（旧镜像不删、族系可回切），而不是出事时找镜像。

## 8. 更新策略四选一

| 策略 | 机制 | 适用 / 代价 |
|---|---|---|
| **重建镜像** | 走构建流水线出新版 → 换族系 | 最干净、可复现；周期长（小时级） |
| **快照/原地补丁** | 在实例上打补丁 → 做成新镜像 | 快；但"实例漂移"，可复现性下降 |
| **内核热补丁** | livepatch 类，不重启修内核 CVE | 救急；仍需最终收敛到新镜像 |
| **bootc / 事务更新** | 镜像化更新 + 原子回滚 | 新范式；需要系统改造 |

> 生产建议：**以"重建镜像"为主干**，热补丁只做应急；每次热补丁都要登记"待收敛到哪个镜像版本"。

## 9. 成本联动：镜像体积 → 系统盘档位 → 账单

| 联动点 | 说明 | 优化动作 |
|---|---|---|
| 镜像体积 ↔ 导入/上传耗时 | 体积大 → 出图慢、导入慢 | 瘦身与稀疏化（见 [[entities/镜像格式 与 离线处理工具链]] §5） |
| 镜像虚拟大小 ↔ 系统盘下限 | 云平台要求系统盘 ≥ 镜像虚拟大小（有些还要求更大） | 控制镜像虚拟大小，别把虚拟大小做大后无法回退 |
| 系统盘容量 ↔ 账单 | 系统盘按容量计费（云盘档位越高单价越高） | 按需定容；扩容容易、缩容难 → 别一次买太大 |
| 重复镜像 ↔ 配额与存储费 | 多地域复制、多个历史版本都占存储 | 保留策略 + 按需复制 |
| 就地补丁 ↔ 运维成本 | 漂移实例的排障成本远高于重建 | 主干走重建流水线 |

> 提醒：**镜像本身在多数云上存储费很低，真正的成本在"系统盘容量 × 实例数量 × 时间"** ——
> 优化优先级应该是"系统盘定容"高于"镜像瘦身"。

## 10. 治理清单（可直接作为制度项）

```
□ 命名规范落地（产品/版本/架构/用途/构建号/git）
□ 每个版本带 sha256 与构建元数据（版本/组件清单）
□ 台账：镜像↔实例双向可查；删除前必查引用
□ 族系语义明确：哪些场景用族系、哪些锁定镜像 ID
□ 保留策略：最近 N 版 + 季度基线；失败/过期镜像定时清理
□ 共享与复制白名单；加密镜像的密钥治理
□ 回滚演练：至少验证一次"回切旧镜像 ID"能成功
□ 更新策略：主干=重建；热补丁登记待收敛清单
□ 系统盘定容评审（避免镜像虚拟大小倒逼大盘）
```
