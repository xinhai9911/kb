# 加密算法总览与分类

> 本文是加密算法深挖的入口，从**工程系统视角**而非纯数学视角串起整套体系。
> 后续各文：[[concepts/对称加密 AES与ChaCha20]]、[[concepts/非对称加密与密钥交换 RSA_ECC_ECDHE]]、

## 1. 为什么要加密：三个基本目标

| 目标 | 含义 | 提供方 |
|------|------|--------|
| **机密性** (Confidentiality) | 数据不被窃听 | 对称/非对称加密 |
| **完整性** (Integrity) | 数据不被篡改 | 哈希 / MAC / AEAD |
| **认证** (Authentication) | 通信对方是其所声称的身份 | 非对称签名 / 证书 / MAC |

真实协议（如 TLS）把三者叠加：握手阶段用非对称做**认证+密钥协商**，记录层用对称做**批量机密性+完整性**。

## 2. 四大类与在协议栈的位置

```
应用数据
  │
  ├─ 哈希/MAC  ──── 完整性校验、HMAC、AEAD 的认证标签
  │
  ├─ 对称加密 ──── 记录层批量加密（AES-GCM / ChaCha20-Poly1305）
  │               快、密钥短，但密钥分发难
  │
  ├─ 非对称加密 ── 密钥交换 / 签名（RSA / ECC / ECDHE）
  │               慢、密钥长，只用于少量数据（协商对称密钥、签证书）
  │
  └─ TLS 协议 ──── 把上面三者编排成「握手 + 记录层」
                   见 [[concepts/TLS 协议握手与记录层]]
```

## 3. 对称 vs 非对称（工程取舍）

| 维度 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 速度 | 极快（GB/s 级，有硬件指令） | 慢（ms 级/次，CPU 密集） |
| 密钥 | 一个共享密钥，分发是难题 | 公钥公开、私钥保密 |
| 用途 | 批量数据加密 | 密钥协商、数字签名、认证 |
| 典型 | AES-128/256-GCM、ChaCha20 | RSA-2048+、ECDSA P-256、X25519 |
| 硬件 | AES-NI / 网络处理器 offload | 协处理器/TPM/QSFP 内 TLS |

**核心工程结论**：任何高性能加密系统都采用「非对称协商 + 对称传输」的混合模式。纯非对称加密批量数据在吞吐上不可行。

## 4. 分组密码的模式（mode）决定了安全语义

对称分组密码（如 AES）一次只加密 16 字节块，需要**模式**把块拼成任意长度报文：

| 模式 | 特点 | 完整性 | 备注 |
|------|------|--------|------|
| ECB | 每块独立加密 | 无 | **禁用**：相同明文→相同密文，暴露结构 |
| CBC | 链式 IV | 无（需外挂 MAC） | 曾主流，现被 AEAD 取代 |
| CTR | 计数器流模式 | 无 | 可并行，ChaCha20 即用此思想 |
| **GCM** | 计数器 + 认证 | **有**（AEAD） | TLS 1.2/1.3 默认首选 |
| **ChaCha20-Poly1305** | 流密码 + Poly1305 | **有**（AEAD） | 无 AES 指令的设备首选 |

**AEAD**（Authenticated Encryption with Associated Data）= 加密+完整性一体，是现代协议强制要求。绝不手动「加密后再 HMAC」，直接用 GCM/ChaCha20-Poly1305。

## 5. 密钥长度与安全强度对照

| 算法 | 密钥长度 | 等价安全强度 | 备注 |
|------|---------|-------------|------|
| AES-128 | 128 bit | ~128 bit | 主流，抗量子前够用 |
| AES-256 | 256 bit | ~256 bit | 机密等级 |
| RSA | 2048 bit | ~112 bit | 逐步淘汰，建议 3072+ |
| ECDSA / ECDH P-256 | 256 bit | ~128 bit | 与 AES-128 匹配 |
| X25519 / Ed25519 | 256 bit | ~128 bit | 现代、实现简单 |
| SHA-256 | 256 bit 输出 | 128 bit 抗碰撞 | 配套 AES-128 |

经验法则：**对称 128 / 椭圆曲线 256 / RSA 3072** 是当前推荐下限。

## 6. 性能视角：加密是数据面的关键成本

在网络数据面（[[concepts/Nginx 架构与事件模型]]、[[20-protocols/VPP 2|VPP]]）中，TLS 加解密常是 CPU 瓶颈：

- 无加速时，单核 TLS 吞吐约 100–300 Mbps；启用 AES-NI 后可达数 Gbps。
- 大量短连接（TLS 握手）受非对称运算（ECDHE + 证书验证）制约，需 **session 复用 / 0-RTT / TLS offload**。
- 侧信道（时序/缓存）迫使关键实现走**常量时间**代码，牺牲部分性能换安全（见 [[concepts/侧信道攻击与常量时间实现]]）。
