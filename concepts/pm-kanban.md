# 看板方法

## 概述

看板（Kanban，源自日语"看板/信号卡"）起源于丰田生产系统，后由 David Anderson 引入 IT 领域。与 Scrum 的固定 Sprint 不同，看板采用**持续流动**模型。

## 四大核心原则

1. **从现状开始** — 不改变现有角色和流程，直接可视化
2. **追求渐进式变革** — 小步改进，不搞颠覆
3. **尊重当前流程** — 保留有效的角色/职责/流程
4. **鼓励各级领导力** — 每个人都能推动改进

## 六大实践

1. **可视化工作流** — 看板面板（待办/进行中/已完成）
2. **限制 WIP** — 限制各阶段同时处理的任务数
3. **管理流动** — 监控周期时间，优化吞吐量
4. **明确过程策略** — 定义"完成"标准与流转规则
5. **建立反馈机制** — 定期回顾，持续改进
6. **协作式改进** — 基于数据做流程调整

## 关键指标

- **Cycle Time** — 任务从开始到完成的时间
- **Throughput** — 单位时间内完成的任务数
- **CFD（累积流图）** — 可视化工作流动状态

## Scrum vs Kanban

| 维度 | Scrum | Kanban |
|------|-------|--------|
| 交付节奏 | 固定 Sprint | 持续交付 |
| 变更机制 | Sprint 内不接新需求 | 随时可加入 |
| 角色 | 三角色固定 | 无强制角色 |
| WIP 限制 | 隐式（Sprint 范围） | 显式（每列限制） |
| 度量 | Velocity / Burn-down | Cycle Time / Throughput |
