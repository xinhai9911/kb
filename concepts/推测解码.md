# 推测解码：LLM 加速技术

> **一句话**：推测解码 = 小模型"猜" + 大模型"验"，在不损失质量的前提下加速 LLM 推理。

## 为什么需要推测解码

LLM 的自回归解码是**逐 token 串行**的，每次只能生成一个 token，GPU 利用率低：

```
传统自回归解码：
  Step 1: [全部 KV Cache] → token_1  (GPU 利用率 ~10%)
  Step 2: [全部 KV Cache] → token_2  (GPU 利用率 ~10%)
  Step 3: [全部 KV Cache] → token_3  (GPU 利用率 ~10%)
  Step 4: [全部 KV Cache] → token_4  (GPU 利用率 ~10%)
  时间: 4 步，每步一次前向传播
```

推测解码的核心思想：让**小模型**快速生成多个候选 token，然后让**大模型一次性并行验证**：

```
推测解码：
  小模型: 生成 [token_1', token_2', token_3', token_4']  (快速，4 步)
  大模型: 一次性验证 [token_1', token_2', token_3', token_4']
  结果:   [token_1✓, token_2✓, token_3✗] → 保留前 2 个 + 重新采样
  时间: 1 步验证（vs 传统 3-4 步）
```

## 核心原理

### 工作流程

```
┌─────────────────────────────────────────────────────┐
│                 推测解码流程                          │
├─────────────────────────────────────────────────────┤
│                                                     │
│  Draft Model (小模型, e.g., 0.5B)                   │
│  ┌─────────────────────────────────────────┐        │
│  │ Step 1: 生成 token_1'                    │        │
│  │ Step 2: 生成 token_2'                    │        │
│  │ Step 3: 生成 token_3'                    │        │
│  │ Step 4: 生成 token_4'                    │        │
│  └─────────────────────────────────────────┘        │
│                     ↓                               │
│  Target Model (大模型, e.g., 70B)                   │
│  ┌─────────────────────────────────────────┐        │
│  │ 一次性验证所有候选 token                   │        │
│  │ [token_1'✓, token_2'✓, token_3'✗, ...]  │        │
│  │ 从 token_3 重新采样                      │        │
│  └─────────────────────────────────────────┘        │
│                     ↓                               │
│  输出: [token_1, token_2, token_3*]                 │
│  (token_1/token_2 来自 draft, token_3* 重新采样)    │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 数学保证

推测解码的一个关键性质：**输出分布与直接用大模型解码完全相同**。

验证过程使用"拒绝采样"（Rejection Sampling）：
1. Draft 模型生成 token，概率为 `q(x)`
2. Target 模型验证，概率为 `p(x)`
3. 接受概率：`min(1, p(x)/q(x))`
4. 若拒绝，从修正分布 `max(0, p(x)-q(x))` 重新采样

```python
import torch

def speculative_decode_step(draft_model, target_model, prompt, gamma=4):
    """
    gamma: draft 模型每次猜测的 token 数
    """
    # 1. Draft 模型快速生成 gamma 个候选 token
    draft_tokens = []
    draft_probs = []
    x = prompt
    for _ in range(gamma):
        q = draft_model.get_probs(x)  # Draft 模型的概率分布
        token = torch.multinomial(q, 1)
        draft_tokens.append(token)
        draft_probs.append(q[token])
        x = torch.cat([x, token])
    
    # 2. Target 模型一次性并行验证
    target_probs = target_model.get_probs_all(
        torch.cat([prompt] + draft_tokens)
    )  # 一次前向传播得到所有位置的概率
    
    # 3. 逐个验证
    accepted = 0
    for i in range(gamma):
        p = target_probs[i][draft_tokens[i]]  # Target 概率
        q = draft_probs[i]                      # Draft 概率
        
        # 拒绝采样
        if torch.rand(1) < min(1, p / q):
            accepted += 1  # 接受
        else:
            # 拒绝，从修正分布重新采样
           修正分布 = torch.clamp(p - q, min=0)
            修正分布 = 修正分布 / 修正分布.sum()
            new_token = torch.multinomial(修正分布, 1)
            draft_tokens[accepted] = new_token
            break
    
    return draft_tokens[:accepted + 1]
```

## 加速效果

### 理论加速比

加速比取决于 Draft 模型与 Target 模型的**接受率**（Acceptance Rate）：

```
加速比 = (γ × α + 1) / (γ × c + 1)
其中：
  γ = draft 模型猜测长度（通常 4-8）
  α = 平均接受率（通常 0.6-0.8）
  c = 验证成本比（通常 0.1-0.3，取决于模型大小比）
```

### 实际加速效果

| 场景 | Draft 模型 | Target 模型 | 加速比 | 接受率 |
|------|-----------|-------------|:------:|:------:|
| 代码生成 | CodeLlama-1B | CodeLlama-34B | 2.5-3x | 0.75 |
| 文本摘要 | Llama-2-7B | Llama-2-70B | 2-2.5x | 0.70 |
| 对话生成 | Phi-2 | Llama-3-70B | 1.8-2.2x | 0.65 |
| 翻译 | NLLB-200 | Llama-3-70B | 2-2.8x | 0.72 |

> 加速比因任务、模型、prompt 而异。高度重复性任务（如代码、模板文本）接受率更高。

## 变体与改进

### 1. 树状推测解码（Tree-based Speculative Decoding）

Draft 模型生成多条候选路径，Target 模型一次验证整棵树：

```
Draft 生成（树状）：
        token_A
       /       \
  token_B1    token_B2
   /    \       |    \
C1      C2     C3    C4

Target 验证：一次前向传播验证整棵树
→ 选择概率最高的路径
```

### 2. 自推测解码（Self-Speculative Decoding）

用模型自身的**浅层**作为 Draft 模型，无需额外小模型：

```
大模型（32层）:
  浅层 Draft: 使用前 8 层快速生成候选
  完整验证:  使用全部 32 层验证
```

### 3. Medusa：多头并行推测

在大模型顶部添加多个"猜测头"，并行生成多个候选 token：

```
大模型 backbone
    ├── Head 1: 预测 token_t+1
    ├── Head 2: 预测 token_t+2
    ├── Head 3: 预测 token_t+3
    └── Head 4: 预测 token_t+4

所有候选 token 一次性验证
```

### 4. EAGLE：特征级别推测

Draft 模型在**特征空间**（而非 token 空间）进行推测，接受率更高。

## 实际应用

### vLLM 中使用推测解码

```python
from vllm import LLM, SamplingParams

# 需要指定 draft model
llm = LLM(
    model="meta-llama/Llama-3-70B-Instruct",
    speculative_model="meta-llama/Llama-3-8B-Instruct",  # Draft 模型
    num_speculative_tokens=5,  # 每次猜测 5 个 token
    speculative_max_model_len=4096,
)

outputs = llm.generate(["Hello"], SamplingParams(max_tokens=100))
```

### Ollama 中使用推测解码

```bash
# Ollama 支持自动推测解码
ollama run llama3:70b-instruct --num-speculative-tokens 5
```

## 局限性

| 局限 | 说明 |
|------|------|
| **额外内存** | 需要同时加载两个模型 |
| **Draft 模型选择** | 需要与 Target 模型分布接近 |
| **延迟 vs 吞吐** | 主要降低延迟，吞吐提升有限 |
| **不适用场景** | 高熵任务（创意写作）接受率低 |
