# 大模型评测与基准

## 主流评测基准

| 基准名称 | 评测能力 | 难度等级 | 典型模型表现（参考） |
|---|---|---|---|
| MMLU | 通用知识与推理（57个学科） | 中等 | GPT-4 ~86%, Claude 3 ~86% |
| HumanEval | 代码生成与补全 | 中高 | GPT-4 ~92%, Claude 3 ~84% |
| GSM8K | 小学数学应用题 | 中等 | GPT-4 ~95%, Claude 3 ~92% |
| MATH | 竞赛级数学推理 | 高 | GPT-4 ~52%, Gemini Ultra ~59% |
| LMSYS Arena | 人类偏好对战排名 | 混合 | 基于 Elo 评分的众包排名 |
| ARC-Challenge | 科学推理（小学至高中） | 中等 | GPT-4 ~96% |
| HellaSwag | 常识推理与场景补全 | 低 | 主流模型均 >95%，区分度降低 |
| WinoGrande | 常识消歧 | 低 | 主流模型均 >85% |
| GPQA | 研究生级问答（专家出题） | 极高 | GPT-4 ~56%, 专家 ~81% |
| MT-Bench | 多轮对话质量 | 中等 | GPT-4 ~9.0/10（LLM-as-Judge） |

> 注意：模型表现数据为参考值，随版本迭代变化。

## 评测方法论

### 人工评测

- **人类偏好对战**（如 LMSYS Chatbot Arena）：随机两两对比，人类盲评选择更优回复，计算 Elo / Bradley-Terry 评分。
- **专家标注**：领域专家对模型输出进行多维度评分（准确性、流畅度、安全性等）。
- **优点**：最贴近真实用户体验。
- **缺点**：成本高、速度慢、评判标准主观性强、难以规模化。

### 自动评测

- **精确匹配（Exact Match）**：答案与标准答案完全一致计为正确（如 GSM8K）。
- **编程执行**：运行生成代码验证正确性（如 HumanEval 通过率 Pass@k）。
- **嵌入相似度**：使用 embedding 计算生成答案与标准答案的语义相似度。
- **优点**：可规模化、可复现、客观。
- **缺点**：难以衡量开放性任务的质量。

### LLM-as-Judge

- 使用强模型（如 GPT-4）作为裁判，对其他模型的输出进行评分。
- **评测框架**：MT-Bench、AlpacaEval 等均采用此方法。
- **优点**：成本低于人工、可规模化、评分一致性较好。
- **缺点**：存在位置偏见（偏好第一个回答）、冗长偏见、自我偏好等问题。

## 中国模型评测

| 基准名称 | 评测能力 | 说明 |
|---|---|---|
| C-Eval | 中文综合能力（52个学科） | 覆盖中学到研究生，中国本土知识 |
| CMMLU | 中文多任务理解（67个学科） | 侧重中国特有知识（法律、历史等） |
| SuperCLUE | 中文开放域综合评测 | 多轮、多维度中文能力评估 |

> 中国评测基准弥补了英文基准在中文语境和本土知识方面的不足。

## 评测陷阱与挑战

### 数据污染（Data Contamination）

- 模型训练数据中可能包含评测基准的测试集数据，导致评测分数虚高。
- **检测方法**：n-gram 重叠检测、canary string 注入、困惑度异常分析。
- **应对**：持续更新基准（如动态生成新题目）、使用 held-out 私有测试集。

### 过拟合 Benchmark

- 模型在特定 benchmark 上过度优化，但泛化能力不足。
- **表现**：某 benchmark 分数极高，实际用户体验无明显提升。
- **应对**：多基准综合评估、重视真实场景评测（Arena）。

### 其他挑战

- **基准饱和**：某些基准（如 HellaSwag）已难以区分前沿模型。
- **评测维度单一**：单一分数无法反映模型在不同场景下的表现差异。
- **多模态评测滞后**：图像、视频、音频等模态的评测基准尚不成熟。
- **安全性评测**：对抗鲁棒性、偏见检测、有害内容生成等评测仍在发展中。
