# 韧性设计

> 分布式系统（[[concepts/分布式系统基础]]）默认会故障。韧性 = 让局部故障不雪崩成全局。本文是「容错设计模式」工具箱。

## 1. 超时（最基础却最常忘）

- 任何跨网络调用**必须有超时**，否则一个慢依赖拖死调用线程池。
- 超时应**逐层递减**（上层总超时 > 各下游之和），避免「上游等 5s 但下游已 30s 返回无用结果」。
- 区分**连接超时**与**读写超时**。

## 2. 重试与退避

| 策略 | 说明 | 风险 |
|------|------|------|
| 立即重试 | 简单 | 易把故障方打挂（重试风暴） |
| 固定间隔 | 稍好 | 仍可能共振 |
| **指数退避 + 抖动** | 2^n + 随机 | 标准做法，错开请求 |
| 重试上限 | 最多 N 次 | 防无限循环 |

> **重试只用于幂等操作**（[[concepts/分布式系统基础]] §5）。非幂等重试会重复扣款/下单。
> 配合 **jitter**：`sleep = base * 2^attempt + random(0, base)`。

## 3. 熔断（Circuit Breaker）

```
正常 ──失败率超阈值──► 打开(直接失败, 不打电话)
   ▲                      │
   │ 冷却时间到            ▼
   └──── 半开(放少量探活)──► 成功则关闭, 失败则回打开
```

- 熔断保护**故障方**：它挂了就别再发请求，给其恢复时间。
- 三态：Closed / Open / Half-Open。
- 参数：错误率阈值（如 50%）、滑动窗口、冷却时间。
- 实现：resilience4j、Sentinel、Envoy 内置。

## 4. 限流（Rate Limiting）

| 算法 | 特点 |
|------|------|
| 计数器/滑动窗口 | 简单，滑动窗口更平滑 |
| **令牌桶** | 允许突发（桶里有余量就放行），平均限速率 |
| **漏桶** | 恒定输出速率，平滑但难突发 |
| 并发数限制 | 限制同时在途请求数（保护线程池） |

- 多层限流：网关层（全局）+ 服务层（单实例）+ 依赖方（保护下游）。
- 与网关结合（[[concepts/Nginx 架构与事件模型]] 的 `limit_req`/`limit_conn`）。

## 5. 舱壁隔离（Bulkhead）

- 把资源**分区隔离**：A 依赖的线程池满了，不影响 B 依赖。
- 类比船舱：一个舱进水不沉船。
- 实现：独立线程池 / 连接池 / 信号量隔离不同下游。

## 6. 降级与兜底（Fallback）

- 非核心功能在压力下**降级**：推荐挂了返回默认列表，评论挂了隐藏模块。
- 兜底数据：缓存旧值、静态页、默认值。
- 降级开关：手动 + 自动（结合错误预算，[[concepts/可观测性工程]] §5）。

## 7. 背压（Backpressure）

- 下游处理不过来时，**反向通知上游减速**，而非无限堆积 OOM。
- 体现：消息队列长度、reactive 的 onBackpressureDrop、TCP 窗口。
- 配合限流/舱壁一起防止雪崩。

## 8. 雪崩防护组合拳

```
请求 → 限流(令牌桶) → 舱壁(隔离资源) → 调用(超时) → 失败则 重试(退避+幂等)
                                          ↓ 失败率高
                                       熔断(开路, 直接降级兜底)
```
每一层都靠 [[concepts/可观测性工程]] 的指标触发与观测。
