# 软件项目文档体系

## 概述

"文档不如可工作的软件"（敏捷宣言），但关键文档依然是**沟通契约和决策依据**。关键不在于文档量，而在于**选择合适的文档化程度**。

## 项目全生命周期文档清单

### 启动阶段

| 文档 | 用途 | 读者 |
|------|------|------|
| 项目章程 | 正式授权 PM，定义目标和关键干系人 | 高管、PM |
| 可行性研究报告 | 评估技术/经济/运营可行性 | 决策层 |
| 干系人登记册 | 识别所有干系人及其影响力 | PM |

### 计划阶段

| 文档 | 用途 |
|------|------|
| 项目管理计划 | 各子计划集成（范围/进度/成本/质量/风险等） |
| 需求规格说明书（SRS） | 功能与非功能需求的完整描述 |
| 架构设计文档（ADD） | 系统架构、模块分解、接口定义 |
| 测试计划 | 测试策略、范围、资源、环境 |
| 风险登记册 | 识别风险 + 应对措施 |

### 执行与监控阶段

| 文档 | 用途 |
|------|------|
| 项目状态报告 | 每周/每 Sprint 向干系人汇报 |
| 变更日志 | 记录所有已审批/拒绝的变更请求 |
| 会议纪要 | 关键决策和行动项记录 |
| 技术设计文档 | 详细模块设计 |
| 用户手册 | 最终用户操作指南 |

### 收尾阶段

| 文档 | 用途 |
|------|------|
| 项目总结报告 | 经验教训、实际 vs 计划、建议 |
| 运维移交文档 | 部署拓扑、监控配置、故障处理 |
| 验收报告 | 客户/干系人正式签收 |

## 度与量

- **敏捷推荐**：可工作的软件 > 详尽的文档
- **合规行业**（金融/医疗/军工）：文档是法规要求
- **"恰好充足"原则**：文档能支撑后续决策和理解即可
- **Living Document**：文档应随项目演进持续更新
