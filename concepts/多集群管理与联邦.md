# 多集群管理与联邦

> 单集群有物理与逻辑上限：单集群跨不了地域、单集群挂了全部业务停、多租户隔离不够彻底。
> 生产级 K8s 迟早要面对「多个集群怎么管」的问题。见 [[synthesis/Kubernetes 技术全景综述]]。

---

## 1. 为什么需要多集群

| 驱动因素 | 说明 |
|----------|------|
| **地域分布** | 低延迟接入（用户就近访问）、数据主权（GDPR 要求数据不出境） |
| **灾备（DR）** | 一个集群挂了，另一个接管（RPO/RTO 目标） |
| **多租户隔离** | 不同团队/业务线用独立集群，避免「吵闹邻居」 |
| **合规要求** | 金融/政务要求物理隔离 |
| **环境隔离** | dev/staging/prod 各一个集群，避免测试影响生产 |

---

## 2. 多集群架构模式

| 模式 | 适用场景 | 复杂度 |
|------|----------|:------:|
| **独立集群 + 统一管理** | 多环境/dev-prod 分离 | 低 |
| **Hub-Spoke（中心-分支）** | 中心集群管理N个边缘集群 | 中 |
| **Peer-to-Peer（对等）** | 跨地域对等互联 | 高 |
| **Control Plane 联邦** | 统一 API 入口管理多集群资源 | 高 |

---

## 3. Cluster API（集群生命周期管理）

Cluster API（CAPI）是 K8s SIG cluster-lifecycle 的项目，用声明式方式管理集群的**创建/升级/删除**：
```yaml
apiVersion: cluster.x-k8s.io/v1beta1
kind: Cluster
metadata:
  name: prod-cluster
spec:
  clusterNetwork:
    pods:
      cidrBlocks: ["192.168.0.0/16"]
  controlPlaneRef:
    apiVersion: controlplane.cluster.x-k8s.io/v1beta1
    kind: KubeadmControlPlane
    name: prod-controlplane
  infrastructureRef:
    apiVersion: infrastructure.cluster.x-k8s.io/v1beta1
    kind: AWSCluster
    name: prod-cluster
```

- **Provider 无关**：AWS（CAPA）、Azure（CAPZ）、vSphere（CAPV）、bare-metal（CAPM）。
- **与 Terraform 互补**：Terraform 拉基础设施（VPC/EC2），CAPI 管 K8s 集群生命周期。

## 4. Submariner（跨集群网络）

Submariner 让不同集群的 Pod/Service 之间**直接通信**（无需 NodePort/LB）：
- **VXLAN 隧道**：跨集群 Pod CIDR 通过加密隧道互通。
- **GlobalNet**：解决 Pod CIDR 冲突（自动重分配）。
- **Service Discovery**：远端集群的 Service 可通过 `clusterset.local` DNS 访问。

```
Cluster A (Pod: 10.0.0.0/16)  ←──Submariner隧道──→  Cluster B (Pod: 10.1.0.0/16)
       │                                                    │
       └── Service A ←── 跨集群 DNS 解析 ──→ Service B ────┘
```

---

## 5. Liqo（轻量联邦）

Liqo 比 Submariner 更进一步——把远端集群的资源**虚拟化为本地集群的一部分**：
- **Virtual Node**：远端集群表现为本地一个虚拟节点，Pod 调度到虚拟节点 = 实际跑在远端。
- **无需修改 Pod CIDR**：自动处理网络重叠。
- **适合场景**：边缘计算（云端+边缘集群统一调度）、混合云。

---

## 6. 多集群 Service API

K8s 社区正在标准化多集群 Service（`MultiClusterService` CRD）：
- **服务发现**：跨集群 Service 自动注册到所有关联集群的 DNS。
- **负载均衡**：请求自动路由到最近/最健康的集群。
- **与 Gateway API 集成**：多集群 Ingress 统一入口。

---

## 7. GitOps 多集群交付

用 ArgoCD 的 **ApplicationSet** 为多个集群批量部署（[[entities/GitOps 与 ArgoCD 实战]] §4）：
```yaml
# 一个 ApplicationSet 自动生成 dev/staging/prod 三个 Application
generators:
  - clusters:
      selector:
        matchLabels:
          env: production
```
