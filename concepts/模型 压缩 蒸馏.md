# 模型压缩与知识蒸馏

## 压缩技术分类

| 技术类别 | 代表方法 | 压缩比 | 精度损失 | 是否需要训练 | 典型场景 |
|---|---|---|---|---|---|
| 知识蒸馏 | 白盒蒸馏、黑盒蒸馏 | 5x-50x | 中 | 是 | 训练小型部署模型 |
| 结构化剪枝 | 移除注意力头/FFN层 | 2x-4x | 低-中 | 是（微调） | 减少模型宽度/深度 |
| 非结构化剪枝 | SparseGPT, Wanda | 2x-10x | 低 | 部分需要 | 稀疏加速（需专用硬件） |
| 量化 | PTQ, QAT | 2x-8x | 低 | 部分需要 | 降低推理显存/加速 |
| 低秩分解 | LoRA, SVD | 2x-4x | 低 | 是 | 微调适配小参数量 |

## 知识蒸馏

### 白盒蒸馏（White-Box）

- **前提**：可访问教师模型的内部状态（logits、中间层激活）。
- **方法**：
  - **Logit 蒸馏**：最小化学生与教师输出概率分布的 KL 散度
  - **特征蒸馏**：对齐学生与教师中间层的隐藏状态
  - **注意力蒸馏**：模仿教师的注意力权重分布
- **流程**：教师模型推理 → 收集 soft labels → 学生模型同时拟合 soft labels 和 ground truth
- **典型工具**：DistilBERT、TinyBERT、MiniLM
- **优点**：充分利用教师内部信息，蒸馏效果好。
- **缺点**：需要教师模型代码和权重，计算资源需求高。

### 黑盒蒸馏（Black-Box）

- **前提**：仅可访问教师模型的 API 输入输出，无法获取内部状态。
- **方法**：
  - **数据合成**：使用教师生成大量高质量训练数据（如 Alpaca、WizardLM）
  - **Chain-of-Thought 蒸馏**：提取教师的推理链作为训练目标（如 Orca、Phi 系列）
  - **输出分布对齐**：通过多次采样近似教师的输出分布
- **流程**：教师 API 推理 → 生成合成数据 → 用于学生模型训练/微调
- **优点**：无需教师模型内部访问，适用商业 API 模型。
- **缺点**：信息损失较大，效果通常不如白盒蒸馏。

## 剪枝方法

### 结构化剪枝

- **原理**：移除整个注意力头、FFN 神经元或整层，直接减小模型结构。
- **方法**：
  - 基于重要性评分的全局剪枝
  - 基于梯度的剪枝（如 movement pruning）
  - LLM-Pruner：利用依赖关系进行结构化剪枝
- **优点**：可直接在标准硬件上加速推理，无需专用稀疏支持。
- **缺点**：精度损失相对较大，压缩比受限。

### 非结构化剪枝

- **原理**：移除模型中的单个权重参数，产生稀疏权重矩阵。
- **方法**：
  - **SparseGPT**：一次性剪枝，无需重新训练，支持 50%-60% 稀疏度
  - **Wanda**：基于权重幅度和激活幅度的乘积进行剪枝，无需梯度计算
- **优点**：高稀疏度下精度损失较小。
- **缺点**：需要专用稀疏计算硬件/库（如 NVIDIA Sparse Tensor Core）才能实际加速。

## 量化方法

### PTQ vs QAT

| 维度 | PTQ（训练后量化） | QAT（量化感知训练） |
|---|---|---|
| 执行时机 | 模型训练完成后 | 训练过程中模拟量化 |
| 是否需要训练 | 否 | 是 |
| 精度损失 | 较大（尤其低位宽） | 较小 |
| 计算成本 | 低 | 高（需要完整训练流程） |
| 适用场景 | 快速部署、资源受限 | 对精度要求极高的场景 |

### 主流量化方法对比

| 方法 | 类型 | 核心思路 | 特点 |
|---|---|---|---|
| GPTQ | PTQ | 基于逐层二阶优化的权重量化 | 需要校准数据集，支持 4/3/2 bit，社区广泛 |
| AWQ | PTQ | 基于激活感知的权重量化，保护重要通道 | 精度优于 GPTQ，速度快，推荐首选 |
| GGUF | PTQ | llama.cpp 定义的量化格式 | CPU 推理友好，格式统一，生态成熟 |
| bitsandbytes | PTQ | 8-bit/4-bit 量化 + 分页优化器 | 集成 HuggingFace 生态，使用简单 |
| QLoRA | PTQ + 微调 | 4-bit NF4 量化 + LoRA 微调 | 显存大幅降低，支持消费级 GPU 微调 |

> 推荐选择：追求精度选 AWQ，追求兼容性选 GGUF，追求简单集成选 bitsandbytes。

## 小模型趋势

近年来出现了多种专为小参数量优化的模型系列：

| 模型系列 | 开发方 | 参数规模 | 核心策略 |
|---|---|---|---|
| Phi 系列 | Microsoft | 1.3B-14B | 高质量合成数据 + 教科书级别数据筛选 |
| Gemma 系列 | Google | 2B-27B | 蒸馏自 Gemini，开源小模型 |
| Grok-mini | xAI | ~8B | 高质量数据训练的小模型 |
| Qwen 系列 | Alibaba | 0.5B-72B | 全参数覆盖，小模型能力突出 |
| Llama 系列 | Meta | 1B-405B | 开源生态，多规模覆盖 |

> 小模型趋势：高质量数据 + 蒸馏 > 增大参数量，小模型在特定任务上可接近大模型表现。
