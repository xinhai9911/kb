# 分布式推理：多 GPU 大模型推理

> **一句话**：当单卡装不下或不够快时，分布式推理将模型拆分到多 GPU/节点上，以通信换算力。

## 为什么需要分布式推理

| 场景 | 挑战 | 分布式方案 |
|------|------|------------|
| 70B 模型 | 单卡 80GB 装不下 | 张量并行切分到 4 卡 |
| 405B 模型 | 需要 16+ 卡 | TP + PP 混合并行 |
| 1M 上下文 | KV Cache 巨大 | EP + PP |
| 低延迟要求 | Prefill 太慢 | 分裂式 prefill-decode |
| 高吞吐场景 | 并发不够 | 多节点 + 负载均衡 |

## 三大并行策略

### 1. 张量并行（Tensor Parallelism, TP）

**核心思想**：将每一层的权重矩阵**按列或按行切分**到多个 GPU 上。

```
GPU 0                          GPU 1
┌─────────────┐               ┌─────────────┐
│ W_q[:, :d/2]│               │ W_q[:, d/2:]│
│ (列切分)    │               │ (列切分)    │
├─────────────┤               ├─────────────┤
│ 输入 x      │               │ 输入 x      │
│     ↓       │               │     ↓       │
│ GEMM: x·W0  │               │ GEMM: x·W1  │
│     ↓       │               │     ↓       │
│ 结果 y0     │   AllReduce   │ 结果 y1     │
│     ←───────│───────────────│ →           │
│     ↓       │               │             │
│ y = y0 + y1 │               │ y = y0 + y1 │
└─────────────┘               └─────────────┘
```

| 维度 | 说明 |
|------|------|
| **切分粒度** | 层内切分（权重矩阵） |
| **通信操作** | AllReduce（每层一次） |
| **通信量** | 2 × hidden_size × sequence_length |
| **适用场景** | 单节点多 GPU（NVLink 高带宽） |
| **GPU 数量** | 2, 4, 8（通常为 2 的幂） |

```bash
# vLLM 张量并行
vllm serve meta-llama/Llama-3-70B-Instruct \
    --tensor-parallel-size 4

# SGLang 张量并行
python -m sglang.launch_server \
    --model-path meta-llama/Llama-3-70B-Instruct \
    --tp-size 4
```

### 2. 流水线并行（Pipeline Parallelism, PP）

**核心思想**：将模型的**不同层**分配到不同 GPU 上，形成流水线。

```
GPU 0: Layer 0-7    GPU 1: Layer 8-15   GPU 2: Layer 16-23  GPU 3: Layer 24-31
┌───────┐          ┌───────┐           ┌───────┐           ┌───────┐
│Layer 0│──→       │Layer 8│──→        │Layer 16│──→       │Layer 24│──→ Output
│Layer 1│          │Layer 9│           │Layer 17│           │Layer 25│
│  ...  │          │  ...  │           │  ...  │           │  ...  │
│Layer 7│──→       │Layer 15│──→       │Layer 23│──→       │Layer 31│
└───────┘          └───────┘           └───────┘           └───────┘
```

| 维度 | 说明 |
|------|------|
| **切分粒度** | 层间切分（按层分配） |
| **通信操作** | Point-to-Point（层间传递） |
| **通信量** | hidden_size × sequence_length（每层一次） |
| **适用场景** | 跨节点（网络带宽有限） |
| **核心挑战** | 气泡（Bubble）导致 GPU 空闲 |

**流水线气泡优化**：

```
朴素 PP（气泡率高）：
GPU 0: [B0][B1][B2][B3][ ][ ][ ][ ]
GPU 1: [ ][B0][B1][B2][B3][ ][ ][ ]
GPU 2: [ ][ ][B0][B1][B2][B3][ ][ ]
GPU 3: [ ][ ][ ][B0][B1][B2][B3]

1F1B 调度（气泡率低）：
GPU 0: [F0][F1][F2][F3][B0][B1][B2][B3]
GPU 1: [ ][F0][F1][F2][F3][B0][B1][B2]
GPU 2: [ ][ ][F0][F1][F2][F3][B0][B1]
GPU 3: [ ][ ][ ][F0][F1][F2][F3][B0]

Interleaved 1F1B（气泡率最低）：
GPU 0: [F0a][F1a][F0b][F1b][B0a][B1a][B0b][B1b]
```

### 3. 专家并行（Expert Parallelism, EP）

**核心思想**：MoE 模型的专家分布在不同 GPU 上。

```
MoE Layer: 8 个专家分布在 4 个 GPU 上

GPU 0: Expert 0, Expert 1
GPU 1: Expert 2, Expert 3
GPU 2: Expert 4, Expert 5
GPU 3: Expert 6, Expert 7

输入 token → Router → 选择 Top-2 专家
  → 如果选中 Expert 0 和 Expert 5
  → All-to-All 通信：GPU 0 发送 token 到 GPU 2
```

| 维度 | 说明 |
|------|------|
| **适用模型** | DeepSeek-V3, Mixtral, Switch Transformer |
| **通信操作** | All-to-All |
| **通信量** | 与专家激活比例成正比 |
| **关键参数** | `--num-experts-per-select`（Top-K） |

## 混合并行策略

实际部署中通常组合多种并行策略：

| 模型规模 | 推荐策略 | GPU 数量 |
|----------|----------|----------|
| 7-8B | TP=1, PP=1 | 1 |
| 13-14B | TP=2, PP=1 | 2 |
| 70B | TP=4, PP=1 | 4 |
| 70B (跨节点) | TP=2, PP=2 | 4 (2节点) |
| 405B | TP=8, PP=2 | 16 |
| 671B (MoE) | EP=8, TP=1, PP=2 | 16 |

```bash
# DeepSeek-V3: EP + TP 混合
vllm serve deepseek-ai/DeepSeek-V3 \
    --tensor-parallel-size 1 \
    --num-experts-per-select 8 \
    --max-model-len 4096

# Llama-3-405B: TP + PP 混合
vllm serve meta-llama/Llama-3-405B-Instruct \
    --tensor-parallel-size 8 \
    --pipeline-parallel-size 2
```

## 分裂式架构（Disaggregated Architecture）

### Prefill-Decode 分离

将 Prefill 和 Decode 分离到不同 GPU，各自优化：

```
传统混合架构：
┌────────────────────────────┐
│ GPU 0: Prefill + Decode    │
│ - Prefill 阻塞 Decode      │
│ - 延迟高，吞吐低           │
└────────────────────────────┘

分裂式架构：
┌──────────────────┐         ┌──────────────────┐
│ GPU 0 (Prefill)  │ ──KV──→ │ GPU 1 (Decode)   │
│ - 专注处理输入    │ Cache   │ - 专注生成输出    │
│ - 高并行度       │ 传输    │ - 高吞吐          │
│ - 低 TTFT        │         │ - 低延迟          │
└──────────────────┘         └──────────────────┘
```

### KV Cache 传输

分裂式架构的关键挑战：KV Cache 在 Prefill GPU 和 Decode GPU 之间传输。

| 传输方式 | 带宽需求 | 延迟 |
|----------|----------|------|
| NVLink（同节点） | 900 GB/s | ~1μs |
| InfiniBand（跨节点） | 400 Gbps | ~10μs |
| PCIe（有限） | 64 GB/s | ~100μs |

## 通信与计算重叠

分布式推理的关键优化：**通信与计算重叠**，隐藏通信延迟。

```
无重叠：
  [计算 A] → [通信 A] → [计算 B] → [通信 B]

有重叠：
  [计算 A] → [通信 A + 计算 B] → [通信 B + 计算 C]
              ↑ 通信与计算并行执行
```
