# 公有云镜像 制作 与 导入 实战

> 原理与三家规范见 [[concepts/KVM 公有云 镜像 适配]]；自动化自检脚本见 `projects/kvm-image-check/`。
> 本文是"要动手时照做"的部分，命令以 RHEL8 系为准。

## 1. 发布前镜像清理清单

镜像一旦发布，会被复制成成百上千台实例。**没清理 = 一批实例共用同一台机器身份**，属于必须做的收尾动作。

### 1.1 机器身份（最高优先级）

```bash
# machine-id 清空（systemd 首次启动会自动生成新的）
truncate -s 0 /etc/machine-id
rm -f /var/lib/dbus/machine-id          # RHEL8 上通常是 /etc/machine-id 的硬链接，一并清掉

# SSH 主机密钥删除（sshd-keygen / cloud-init 首次启动重建）
rm -f /etc/ssh/ssh_host_*

# 授权公钥按需清理（不要把自己的调试公钥带进产品镜像）
rm -f /root/.ssh/authorized_keys
rm -f /home/*/.ssh/authorized_keys
```

> 不清理 machine-id 的后果：同一镜像开出的实例在监控、日志、systemd 日志里 ID 相同，排障时无法区分主机。
> 不清理 SSH 主机密钥的后果：所有实例共享同一主机公钥指纹，等于给出中间人攻击的便利条件。

### 1.2 cloud-init 状态（决定新实例是否重新初始化）

```bash
cloud-init clean --logs --seed
rm -rf /var/lib/cloud/*
```

> 机制见原理页 §8：cloud-init 按 instance-id 判断是否已初始化。状态不清，新实例可能**跳过初始化**，表现为控制台改密码无效、hostname 不更新、公钥不注入。
> 注意：`/etc/cloud/cloud.cfg.d/` 里描述数据源/行为的配置要**保留**，清的是 `cloud.cfg.d` 之外的状态目录。

### 1.3 日志与历史

```bash
journalctl --rotate
journalctl --vacuum-time=1s
find /var/log -type f \( -name '*.log' -o -name '*-????????' \) -exec truncate -s 0 {} \;

rm -f /root/.bash_history /home/*/.bash_history
rm -rf /tmp/* /var/tmp/*
```

### 1.4 网络与 udev 痕迹

```bash
# 旧式持久化网卡命名规则
rm -f /etc/udev/rules.d/70-persistent-net.rules

# NetworkManager keyfile 里写死的 MAC
grep -rl 'mac-address=' /etc/NetworkManager/system-connections/ 2>/dev/null | xargs -r rm -f

# ifcfg 里写死的 HWADDR（保留 DEVICE/BOOTPROTO=dhcp/ONBOOT=yes）
grep -rl '^HWADDR=' /etc/sysconfig/network-scripts/ 2>/dev/null
# ↑ 逐个编辑删除 HWADDR 行，不要整文件删掉
```

### 1.5 宿主虚拟化工具与其它

```bash
yum remove -y open-vm-tools xe-guest-utilities VirtualBox-guest-additions 2>/dev/null
# 关闭 firewalld（云上靠安全组）
systemctl disable --now firewalld 2>/dev/null
# 硬件时钟 UTC
timedatectl set-local-rtc 0
```

## 2. 首次启动失败排障手册

### 2.1 症状 → 根因对照表

| 症状（控制台 / VNC / 串口） | 根因 | 处置 |
|---|---|---|
| `Kernel panic - not syncing: VFS: Unable to mount root fs` | `root=` 指向的设备不存在（UUID 不符或驱动缺） | 核对 grub `root=UUID=` 与 `blkid`；确认 initramfs 含 virtio/nvme（原理页 §5） |
| `dracut-initqueue timeout` 后进 emergency | initramfs 里没有根盘驱动 | 重建 initramfs；确认不是写死 `/dev/nvme0n1pX` |
| `emergency mode` + `Failed to mount /data` | fstab 挂载失败（数据盘不存在且未加 `nofail`） | fstab 加 `nofail,x-systemd.device-timeout=0`（原理页 §3） |
| 启动卡 1~2 分钟后自动继续 | cloud-init datasource 探测超时 | 查 `/var/log/cloud-init.log`；确认元数据可达（原理页 §7） |
| 能登录但网卡无 IP，只有 `lo` | 配置写死 MAC，或网卡被 predictable naming 改名 | 删 `mac-address=`；内核参数加 `net.ifnames=0` |
| 能登录但控制台注入的密码无效 | sshd 禁密码登录 / 内核缺 `CONFIG_FW_CFG_SYSFS` / cloud-init 未重跑 | 逐项核查（原理页 §8） |
| UEFI 实例进不了引导（掉到 UEFI shell / no boot device） | ESP 缺 removable fallback（云上 NVRAM 为空） | 补 `\EFI\BOOT\BOOTX64.EFI`（Arm 为 `BOOTAA64.EFI`） |
| 导入时报 `NoSetRoletoECSServiceAccount` | 未授权 ECS 访问 OSS 的 RAM 角色 | 控制台为账号授权（见 §3.1） |
| 容量扩了但 `df` 没变 | 只扩了云盘，没扩分区/文件系统 | `growpart` + `xfs_growfs`（原理页 §6） |

### 2.2 云上救援路径

**① VNC 管理终端进 GRUB 单用户**

云控制台的 VNC 是图形终端，可看到 GRUB 菜单：选内核行按 `e` → 在内核参数行末尾追加 `rd.break` → `Ctrl-X` 启动，进入 initramfs 的救援 shell：

```bash
mount -o remount,rw /sysroot
chroot /sysroot
passwd root                  # 或修 /etc/fstab、改 /etc/ssh/sshd_config
# SELinux 开启时（RHEL8 默认 enforcing）必须重打标签，否则下次启动会被拒
touch /.autorelabel
exit
exit
```

**② 串口日志**

镜像内核参数里带 `console=tty0 console=ttyS0,115200n8` 时，云控制台的串口输出才能看到**引导早期**日志（kernel/initramfs 阶段）。没加这行，云上只能看到登录之后的内容——排障时这是关键差异。

**③ 云助手下发命令**（系统能起、但网络或登录不通）

阿里云云助手可在不登录的情况下执行 shell；镜像按规范装了云助手 Agent 时可用。

**④ 挂盘到临时实例修复**（最稳）

把故障实例的系统盘卸载，挂到一台正常实例作为数据盘，`chroot` 进去修好再挂回。适合大范围损坏（GRUB、initramfs、fstab 全乱）。

### 2.3 本地离线修复（拿到 qcow2 时首选）

```bash
# 方式一：qemu-nbd 挂载（手工修）
modprobe nbd max_part=16
qemu-nbd -c /dev/nbd0 appliance.qcow2
mount /dev/nbd0p3 /mnt                      # 根分区，按实际布局
chroot /mnt /bin/bash
vi /etc/fstab                               # 或修 grub / 重建 initramfs
exit
umount /mnt && qemu-nbd -d /dev/nbd0

# 方式二：libguestfs 离线编辑（不挂载，更安全，脚本友好）
virt-cat  -a appliance.qcow2 /etc/fstab
virt-edit -a appliance.qcow2 /etc/fstab
virt-ls   -a appliance.qcow2 /boot/efi/EFI/BOOT/
virt-customize -a appliance.qcow2 \
  --run-command 'grub2-mkconfig -o /boot/efi/EFI/redhat/grub.cfg' \
  --run-command 'dracut -f --add-drivers "virtio_blk virtio_scsi nvme"'
```

> `virt-customize` 是产线批量改镜像的主力工具：能在不启动镜像的前提下装包、改配置、跑命令，适合"一批镜像统一补驱动 / 清理身份"。

## 3. 三家导入操作细节

### 3.1 阿里云

1. **上传到 OSS**（建议同地域，走内网加速）：控制台或 `ossutil`
2. **首次导入必须授权 RAM 角色**——否则报 `NoSetRoletoECSServiceAccount` / `InvalidRamRole`；授权 ECS 服务角色访问你的 OSS Bucket
3. **导入自定义镜像**（控制台或 `ImportImage`），逐项参数：

   | 参数 | 说明 |
   |---|---|
   | 架构 | **x86_64 / aarch64 必须与镜像一致**（Arm 见原理页 §9.1） |
   | 启动模式 | BIOS / UEFI / **UEFI-Preferred**（双引导镜像选它通吃） |
   | NVMe 驱动 | 选"支持"（否则新规格选不到该镜像） |
   | 操作系统类型 | Linux / Windows |
   | License 类型 | 按发行版与订阅情况选 |

4. **导入后收尾**：确认镜像状态"可用"；把"NVMe 驱动"属性置为**支持**；镜像与实例必须在同地域（跨地域需先复制镜像）
5. **文件格式**：qcow2 / raw / vhd / vmdk

### 3.2 腾讯云

1. **上传到 COS**
2. **导入镜像**（控制台或 `ImportImage`）：指定镜像名称、COS 地址、**启动模式**（Legacy BIOS / UEFI，须与镜像实际一致）、平台类型
3. **格式**：qcow2 / vhd / raw / vmdk
4. **注意**：系统盘扩容由云侧处理（需 guest 内 growpart 能力，见原理页 §6）

### 3.3 华为云

1. **上传到 OBS**
2. **注册私有镜像**（通过外部镜像文件创建系统盘镜像），关键参数：

   | 参数 | 说明 |
   |---|---|
   | 磁盘设备类型 | **virtio 或 scsi；UEFI 镜像必须 scsi**（virtio-scsi） |
   | 启动方式 | BIOS / UEFI，与镜像实际一致 |

3. **硬性校验**（官方规范）：镜像文件必须非加密；启动分区与系统分区必须在同一磁盘；fstab 不得包含非系统盘的自动挂载（用 `nofail` 规避阻塞）
4. **一键重置密码**：需镜像内装 **CloudResetPwdAgent**，否则控制台重置密码不可用（这是华为云与另两家最大的机制差异）

### 3.4 三家通用注意

- 镜像体积与导入耗时成正比，上传前用 qcow2 压缩
- 导入成功 ≠ 能启动，必须**创建实例实测**（原理页 §12 验收矩阵）
- 跨地域/跨账号 = 云内复制/共享；**跨云不可平移**，只能各自导入

## 4. 镜像自检速查

发布前跑 `projects/kvm-image-check/check-image.sh`，覆盖以下检查项（每一项都对应本文或原理页的一条硬性要求）：

| 检查项 | 对应要求 |
|---|---|
| fstab 无 `/dev/` 硬编码、根用 UUID | 原理页 §3 |
| 非根挂载点带 `nofail` | 原理页 §3 |
| grub `root=UUID=` | 原理页 §1/§3 |
| initramfs 含 `virtio_blk` / `virtio_scsi` / `nvme` | 原理页 §5 |
| ESP removable fallback 存在（按架构判 X64/AA64） | 原理页 §4.2 / §9.1 |
| cloud-init 已安装、状态已清理 | 原理页 §8 |
| machine-id 已清空、SSH 主机密钥已删 | 本文 §1.1 |
| NM keyfile 无 `mac-address=`、无 `70-persistent-net.rules` | 本文 §1.4 |
| `cloud-utils-growpart` 已装 | 原理页 §6 |
| 内核 `CONFIG_FW_CFG_SYSFS=y` | 原理页 §3 |
| 无 LVM / swap（按规范告警） | 原理页 §3 |
| 内核参数含 `net.ifnames=0 console=ttyS0` | 原理页 §7 |

> 脚本输出 PASS / WARN / FAIL 三级与退出码，可直接挂到产线出图流水线里做门禁。
