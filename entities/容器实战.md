# 容器实战（Docker / nerdctl / ctr 命令、镜像构建与排障）

> 原理见 [[concepts/容器原理与运行时]]（Namespace/Cgroups/OverlayFS/OCI 运行时栈）。本文给**可直接复用的命令、构建套路与排障清单**。

---

## 1. 工具选型：用哪个？

| 工具 | 定位 | 谁在用 | 备注 |
|---|---|---|---|
| `docker` | 最经典的 CLI +  daemon（dockerd） | 开发者单机 | 功能全，但 K8s 已不再直接调它 |
| `podman` | 无 daemon、rootless 优先，docker 兼容命令 | 红帽系/安全敏感 | `podman` 命令几乎等同 `docker` |
| `nerdctl` | containerd 的 docker 风格 CLI | K8s 节点调试 | 直接打 containerd，命令最像 docker |
| `ctr` | containerd 原生 CLI | 底层调试 | 命令偏原始，不友好但最直白 |
| `crictl` | CRI 标准 CLI | K8s 节点 | 只用于**查看/调试** K8s 起的容器，不能 build |

> [!info] 为什么这么多？
> 因为运行时分层（见 [[concepts/容器原理与运行时#6. 运行时栈：从 docker run 到内核]]）：`dockerd`/`containerd` 是高层运行时，`runc` 是低层。不同 CLI 只是打在不同层上。`ctr` 打 containerd 原生 API，`nerdctl` 在它之上包了 docker 体验，`crictl` 打 K8s 的 CRI。

## 2. 镜像构建实战

### 2.1 最小可用 Dockerfile

```dockerfile
# ---- 构建阶段 ----
FROM golang:1.22 AS build
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -o /app/server .

# ---- 运行阶段（只拷产物，镜像可小到几 MB）----
FROM gcr.io/distroless/static-debian12
COPY --from=build /app/server /server
USER nonroot:nonroot          # 降权运行
EXPOSE 8080
ENTRYPOINT ["/server"]
```

> [!tip] 多阶段构建是必选项
> 编译期需要完整 toolchain（Go/Node/Maven），运行期只需要二进制。`--from=build` 把产物拷进极简运行镜像，**最终镜像不含编译器、源码、缓存**，既小又缩小攻击面。

### 2.2 Dockerfile 优化清单

| 手段 | 做法 | 收益 |
|---|---|---|
| 层缓存 | 不常变的指令（`FROM`/装系统依赖）放前面，`COPY` 代码放最后 | 改代码不重装依赖 |
| 合并 `RUN` | `RUN apt update && apt install -y xxx && rm -rf /var/lib/apt/lists/*` | 减少层、清缓存 |
| 小基础镜像 | `alpine` / `distroless` / `scratch` | 体积小、漏洞少 |
| BuildKit 并行 | `DOCKER_BUILDKIT=1 docker build .` | 多阶段/多平台并行构建更快 |
| `.dockerignore` | 排除 `.git`、`node_modules`、本地配置 | 避免无用上下文、漏泄密钥 |

```bash
# 构建并打多标签 + 指定平台
DOCKER_BUILDKIT=1 docker build \
  --platform linux/amd64,linux/arm64 \
  -t registry.example.com/myapp:1.2.3 \
  -t registry.example.com/myapp:latest .

# 推送到镜像仓库
docker push registry.example.com/myapp:1.2.3
```

> [!warning] 别把密钥 `COPY` 进镜像
> `COPY .env /app` 后即使后续 `RUN rm`，密钥仍在底层（只是被 whiteout 遮住，仍可从下层提取）。用 **BuildKit secret mount** 或运行时注入（[[concepts/Kubernetes 核心架构与组件]] 的 Secret）。

### 2.3 查看镜像内部（不启动也能验）

```bash
docker images                          # 列出镜像 + 大小 + digest
docker history myapp:1.2.3             # 看每层怎么来的、各层大小
docker inspect myapp:1.2.3             # 看 Entrypoint/Env/Config
docker run --rm -it --entrypoint /bin/sh myapp:1.2.3   # 临时换入口进 shell 看结构
```

## 3. 日常命令速查

### 3.1 生命周期

```bash
# 跑一个容器（前台 + 交互）
docker run -it --name demo ubuntu:22.04 /bin/bash

# 后台跑 + 端口映射 + 卷挂载 + 资源限额
docker run -d --name web \
  -p 8080:8080 \
  -v /data:/data:ro \
  --cpus=2 --memory=512m \
  myapp:1.2.3

docker ps                 # 运行中
docker ps -a              # 含已退出
docker start/stop/restart demo
docker rm -f demo        # 强制删除
docker logs -f --tail 100 demo     # 跟日志
docker exec -it demo /bin/sh       # 进运行中容器
docker inspect demo      # 完整状态（IP/Mounts/State/NetworkSettings）
docker stats             # 实时资源占用（看 cgroup 限额是否生效）
```

### 3.2 清理（开发机常满盘）

```bash
docker system df          # 看空间占用
docker system prune       # 删停止容器 + 悬空镜像 + 网络
docker system prune -a    # 连未被引用的镜像也删（更狠）
docker image prune -a --filter "until=24h"   # 删 24h 前的镜像
```

> [!caution] prune 不可逆
> `prune -a` 会删掉所有「当前没被容器引用」的镜像，包括你刚 build 好还没跑的。CI/生产节点谨慎使用。

## 4. 调试排障清单

### 4.1 容器起不来 / 立刻退出

```bash
docker logs demo                       # 先看应用自己报什么
docker inspect demo | grep -A5 State  # 看 ExitCode / Error / 原因
docker run --rm -it --entrypoint /bin/sh myapp   # 换入口手动跑，看报什么
```

常见原因：
- `exec format error` → 架构不匹配（amd64 镜像跑在 arm 机器），重新 `--platform` 构建。
- `permission denied` → 挂载目录权限 / 需 `--user` / SELinux 标签（加 `:z`/`:Z`）。
- 应用前台退出 → 容器主进程结束即容器结束；确保应用**前台运行**（不要 `service xxx start` 后台化）。

### 4.2 验证隔离是否真的生效（回扣原理）

```bash
# 看容器用了哪些 namespace（与原理篇第 2 章呼应）
docker inspect demo -f '{{.State.Pid}}'        # 拿到容器在宿主的 PID
ls -l /proc/<PID>/ns/                          # 列出该进程的 7 类 namespace
# 每个 ns 后的一串 inode 就是隔离标识，不同容器 inode 不同 = 互相隔离

# 看 cgroup 限额落到哪（原理篇第 3 章）
cat /sys/fs/cgroup/system.slice/docker-<id>.scope/cpu.max   # 2 核 → "200000 100000"
cat /sys/fs/cgroup/system.slice/docker-<id>.scope/memory.max
```

### 4.3 网络不通

```bash
docker network ls                       # 看有哪些网络
docker exec demo ip addr / ip route     # 容器内看 IP/路由（需容器有 ip 命令）
docker exec demo nslookup google.com    # DNS 是否通
# 跨容器通信：放同一 user-defined network 才能用服务名互访
docker network create mynet && docker run --net mynet --name a ...
```

> 容器跨节点互通、Service、Ingress 是 K8s 网络范畴，见 [[concepts/Kubernetes 网络模型]]、[[entities/Cilium 容器网络]]。

### 4.4 OOM / 被 kill（exit 137）

```bash
docker inspect demo -f '{{.State.OOMKilled}}'   # true = 因内存超限额被 OOM Killer 杀
dmesg | grep -i "out of memory"                 # 宿主侧确认
```

> exit code 137 = 128 + 9(SIGKILL)。若 `OOMKilled=true`，调大 `--memory` 或查应用内存泄漏（[[concepts/可观测性工程]]）。

## 5. 从 docker 到 K8s 的心智切换

K8s 1.20+ 移除了 dockershim，kubelet 经 **CRI** 调 containerd/CRI-O（见 [[concepts/容器原理与运行时#6. 运行时栈：从 docker run 到内核]]）。**节点上不该再用 docker 管理 K8s 的容器**，改用 `crictl`：

| docker | crictl（等价语义） | 说明 |
|---|---|---|
| `docker ps` | `crictl ps` | 列 K8s 容器 |
| `docker images` | `crictl images` | 节点镜像 |
| `docker logs <id>` | `crictl logs <id>` | 取日志 |
| `docker exec -it` | `crictl exec -it` | 进容器 |
| `docker inspect` | `crictl inspect` | 详情 |

```bash
# K8s 排障首选还是 kubectl（更上层、信息更全）
kubectl get pod -o wide
kubectl describe pod <pod>        # 看 Events：调度失败/镜像拉取/探针失败
kubectl logs <pod> -c <container>
kubectl exec -it <pod> -c <container> -- /bin/sh
```

> [!warning] 节点上用 docker 起容器会绕过 K8s
> 在 K8s 节点手动 `docker run` 的容器**不受调度器/控制循环管理**，可能和 K8s 抢占资源、破坏预期。只在「调试运行时本身」时用，用完即清。

## 6. 常见坑速查

| 现象 | 根因 | 解法 |
|---|---|---|
| 容器内时间不对 | 默认共享宿主时钟，或 TZ 未设 | 挂 `/etc/localtime` 或设 `TZ` 环境变量 |
| 写文件权限变成 root | 容器内 UID 与宿主映射不一致 | 镜像里 `USER` 指定非 root，或挂卷时对齐 UID |
| 端口映射无效 | 应用监听 `127.0.0.1` 而非 `0.0.0.0` | 改应用监听 `0.0.0.0` |
| 镜像越积越大 | 层未合并、缓存未清 | 多阶段 + 合并 RUN + `.dockerignore` |
| `apt`/`yum` 慢 | 没换源 / 没设代理 | 构建时加源或更换 mirror |
