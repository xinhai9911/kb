# 重构实战：识别并消除代码坏味道

> 原理见 [[concepts/软件设计原则与代码质量]]。本文用「前后代码对比」落地。

## 0. 安全重构纪律

> **没有测试别重构。** 先用 [[concepts/CI_CD与测试策略\|单元测试]] 锁住行为，再小步改，每步跑测试。重构**不改外部行为**，只改内部结构。

## 1. 长函数 → 提取函数

```java
// 前：200 行下单函数，混着校验/计算/持久化/通知
void placeOrder(Order o) {
    if (o.items.isEmpty()) throw ...;
    if (o.user.balance < total) throw ...;
    // 50 行算总价/折扣/运费
    // 30 行写库
    // 20 行发邮件
}

// 后：每个步骤提取为独立、可测、单职责的函数
void placeOrder(Order o) {
    validate(o);
    Money total = calculateTotal(o);      // 纯函数，易测
    persist(o, total);
    notifyUser(o);
}
```
收益：每步可单测、可读、可复用。对应**单一职责**。

## 2. 重复代码 → 提取公共逻辑 / 模板方法

```python
# 前：两处雷同的“读配置+校验+连接”
def connect_mysql(): ...
def connect_redis(): ...   # 大量重复

# 后：抽连接工厂 + 配置校验
def connect(kind, cfg):
    validate_cfg(cfg)
    return FACTORIES[kind](cfg)     # 策略/工厂，见 [[concepts/设计模式精讲]]
```
> [!caution] 勿强行合并"巧合重复"
> 「巧合重复」别强行合并：仅当语义相同才抽。

## 3. 特性依恋 → 搬近数据

```java
// 前：订单模块狂调用户模块算折扣
double discount = user.getLevel().rate() * order.getAmount();

// 后：行为搬回拥有数据的类
double discount = order.calculateDiscount(user);  // 或 user.discountFor(order)
```

## 4. 发散式变更 → 拆类（SRP）

```java
// 前：Report 类既管 SQL 查询、又管 HTML 渲染、又管邮件发送
// 后：拆 Query/ReportRender/Notifier 三职责，各自演进
```

## 5. 长参数列表 → 参数对象

```java
// 前：createUser(name, email, phone, addr, level, ...)
// 后：createUser(UserSpec spec)   // 值对象封装，见 [[concepts/领域驱动设计 DDD|值对象]]
```

## 6. 条件爆炸 → 多态 / 查表

```java
// 前：按类型 if-else 算运费
if (type == EXPRESS) ... else if (type == STANDARD) ... else if (type == ECONOMY) ...

// 后 A：策略模式（[[concepts/设计模式精讲]]）
interface ShippingStrategy { Money fee(Order o); }
Map<Type, ShippingStrategy> strategies = ...;
fee = strategies.get(type).fee(order);

// 后 B（简单场景）：查表
Map<Type, BigDecimal> RATES = Map.of(EXPRESS, 20, STANDARD, 10, ECONOMY, 5);
```
> 加新类型不必改老代码 → 满足 [[concepts/软件设计原则与代码质量|OCP]]。

## 7. 用测试锁行为（示例）

```python
def test_calculate_total_applies_discount():
    o = Order([Item(100), Item(200)])
    assert calculate_total(o) == Money(270)   # 锁住预期，重构后复跑
```

## 8. 重构清单（小步）

1. 写/补测试覆盖待改行为
2. 提取函数（最长最乱的先拆）
3. 去重复、搬特性依恋
4. 长参数→参数对象；条件→策略/查表
5. 每步跑测试，绿灯再继续
6. 跑静态检查（lint）确认无新坏味道
