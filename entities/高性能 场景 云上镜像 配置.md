# 高性能 场景 云上镜像 配置

> 前置：[[entities/CPU 隔离与实时调优]]、[[concepts/DPDK 核心架构]]、[[concepts/CPU 虚拟化与IO穿透]]、[[entities/DPDK 开发实战]]。
> 应用：[[concepts/KVM 公有云 镜像 适配]]（镜像侧约束）、[[concepts/QEMU 设备模型 与 virtio 协议]]（virtio-net）。

## 1. 为什么单独成篇：物理机调优 ≠ 云上可复制

你在物理机上做数据面优化的常规手段，在公有云 KVM 上有一半**不可用**：

| 物理机手段 | 云上是否可用 | 说明 |
|---|---|---|
| BIOS 里开大页 | ❌ | guest 没有"BIOS"，**只能靠内核参数** |
| PCIe 直通物理网卡 | ❌ | 云不给你 pass through host 物理 NIC |
| SR-IOV PF 配置 VF | ❌（一般） | PF 在云厂商手里；少数机型给 VF 或增强网络 |
| 绑核 / 中断亲和 | ✅ | 但要在镜像里固化，且只能用云给的 vCPU 拓扑 |
| IOMMU/VFIO 绑定设备 | ⚠️ 有限 | 云上可绑的设备极少（一般只有云厂商暴露的） |
| 大页 1G + NUMA 绑定 | ✅ | 靠内核参数 + 启动脚本 |

**结论**：云上镜像是"**把原本写在 BIOS 与手工命令里的调优，全部前移到内核参数与持久化配置**"。

## 2. 大页：云上唯一入口是内核参数

物理机在 BIOS 开、或用 `sysctl vm.nr_hugepages`（2M）。**1G 大页必须在启动时预留**（运行期无法分配）：

```
# /etc/default/grub 的 GRUB_CMDLINE_LINUX 追加：
default_hugepagesz=1G hugepagesz=1G hugepages=8
```

```bash
grub2-mkconfig -o /boot/grub2/grub.cfg
# 重启后验证
grep -i huge /proc/cmdline
cat /proc/meminfo | grep -i hugepages        # HugePages_Total 应等于设定值
ls -l /sys/kernel/mm/hugepages/hugepages-1048576kB/nr_hugepages
```

**要点**：

| 要点 | 说明 |
|---|---|
| 数量按**实例内存**留余量 | 8×1G = 8 GiB 被大页锁定，2G 内存实例直接起不来 |
| 云上内存是可变的 | 换规格（放大内存）需同步调整 hugepages 参数 |
| NUMA 感知 | 多 NUMA 实例可加 `hugepagesz=1G hugepages=…` 与 `numa_balancing` 相关参数 |
| 不要只写 2M | DPDK 生产场景通常要 `default_hugepagesz=1G` 才稳 |
| 镜像中固化 | 走 grub 参数 → 新实例开箱即有大页 |

> ⚠️ 把大页参数写进镜像前先算清楚：**大页 + 业务内存 + 页缓存**不能超过实例内存，否则表现为开机后 DPDK 初始化失败或系统 OOM。

## 3. CPU 隔离、中断与固化

```
isolcpus=2-7 nohz_full=2-7 rcu_nocbs=2-7
intel_iommu=on iommu=pt        # 若要用 VFIO（云上一般用不到，但无害）
```

```bash
# 隔离后：把数据面线程绑到隔离核（DPDK --lcores / taskset）
# 中断亲和：把 virtio/NVMe 中断从隔离核挪开
#   查看：cat /proc/interrupts
#   设置：echo <mask> > /proc/irq/<n>/smp_affinity_list
```

**固化方式（云上没有手工步骤，必须自启动）**：

| 方式 | 适用 |
|---|---|
| 内核参数（isolcpus 等） | 只能启动时设置 → 写 grub |
| systemd 单元（`ExecStart=/usr/local/sbin/dpdk-irq-affinity.sh`） | 中断亲和、网卡队列配置、环境准备 |
| cloud-init `runcmd` | 首次启动一次性动作（如生成配置文件） |
| 镜像内预置脚本 + 单元 enable | **推荐**：可重复、可版本化 |

## 4. VFIO 绑定持久化（云上边界要说清）

物理机上常用：

```bash
driverctl set-override 0000:03:00.0 vfio-pci
# 或 ip link set dev ethX down + dpdk-devbind.py -b vfio-pci
```

**云上现实**：可绑定的一般只有云厂商显式暴露的增强网络/智能网卡设备；
普通 ECS/CVM 的网卡是 **virtio-net**，它**不需要也不应该**绑 vfio-pci ——
DPDK 在 guest 里用 **virtio-net 用户态 PMD**（`net_virtio`）即可取得用户态收包能力。

| 场景 | 云上做法 |
|---|---|
| 普通云主机跑 DPDK | `net_virtio` PMD（virtio-net）+ 大页 + 绑核 |
| 需要接近裸机性能 | 选装**增强网络/智能网卡/DPU 机型**（厂商提供直通或 SR-IOV VF） |
| 需要低延迟 RDMA | 云厂商的 RDMA/高速网络产品（如阿里 eRDMA、其他云的同类方案） |

> 若确实要绑 vfio：用 **systemd + driverctl** 固化，并注意云上设备 BDF 每次创建可能变化
> → 用 **设备 ID/驱动匹配**（`driverctl --nosave` 或 udev 规则按 vendor:device 匹配）而不是写死 BDF。

## 5. 镜像里要预置的清单（可直接抄）

| 项 | 落点 | 验证 |
|---|---|---|
| 1G 大页 | `/etc/default/grub` → mkconfig | `/proc/meminfo` HugePages_Total |
| CPU 隔离 | 同上 | `cat /proc/cmdline`、`taskset -pc <pid>` |
| 中断亲和脚本 | `/usr/local/sbin/` + systemd 单元 enable | `cat /proc/interrupts` 亲和掩码 |
| 运行时依赖 | dpdk、numactl、driverctl、kernel-devel（若编译 PMD） | `rpm -q` |
| 设备驱动 | `uio`/`vfio-pci` 模块（如需）、`virtio` 内置 | `lsmod`、`lsinitrd \| grep virtio` |
| 网卡待办 | systemd 单元里配置 virtio-net 多队列/RSS | `/sys/class/net/eth0/queues/` |
| 自检 | 业务自带 + `check-image.sh`（驱动/内核参数项） | 见 projects/kvm-image-check |

## 6. 云上验收该测什么（别只测"能起来"）

| 维度 | 测法 | 关注 |
|---|---|---|
| 大页可用 | `dpdk-hugepages.py -s` 或 DPDK `--huge-unlink` 初始化 | 数量与 NUMA 分布 |
| PMD 绑定 | `dpdk-devbind.py -s` | virtio-net 出现在用户态 |
| 吞吐/时延 | 业务基准（如 `testpmd` + 对端打流） | 与物理机差距、是否被 vCPU 抢占 |
| 隔离生效 | `cat /proc/cmdline`、`taskset`、`perf` 看迁移 | 是否仍在共享核上 |
| 中断分布 | `/proc/interrupts` | 是否落在隔离核上（落在隔离核 = 干扰数据面） |
| 规格变更后 | 换实例规格再跑一遍 | 大页/拓扑假设是否还成立 |
| 热迁移影响 | 若开启，观察时延毛刺 | 云上热迁移会带来停顿 |

## 7. 常见坑

| 现象 | 原因 | 处置 |
|---|---|---|
| DPDK 启动报无法分配大页 | 参数没生效 / 数量超过内存 / 未预留 1G | 核对 `/proc/cmdline` 与 `meminfo`；调小数量 |
| 开机后系统 OOM | 大页锁定内存过多 | 减 hugepages 或加大实例内存 |
| 性能远低于物理机 | 走的是 virtio-net 默认路径、未绑核、中断在隔离核上 | 见 §3；核对 PMD 与队列数 |
| `driverctl` 绑定重启失效 | 未持久化 / 设备 BDF 变了 | 用 udev 规则或 `driverctl --nosave`，禁用写死 BDF |
| 想直通物理网卡 | 公有云不提供 | 改走增强网络机型或 virtio PMD |
| 换规格后 DPDK 起不来 | 大页/NUMA 假设失效 | 把大页数量做成启动参数或按内存自适应脚本 |
