# 镜像格式 与 离线处理工具链

> 原理：[[concepts/KVM 公有云 镜像 适配]]（规范与形态）、[[concepts/Linux 启动链 与 引导]]（起不来的原因）。
> 清理与排障清单：[[entities/公有云镜像 制作 与 导入 实战]]。自检脚本：`projects/kvm-image-check/`。

## 1. 镜像格式全景

| 格式 | 特征 | 稀疏 | 快照链 | 云平台支持（阿里/腾讯） | 典型用途 |
|---|---|---|---|---|---|
| **raw** | 裸字节，无元数据；大小 = 磁盘容量 | 需 FS 层支持 | 无 | ✅ | `dd` 产物、最通用 |
| **qcow2** | QEMU 原生；支持压缩、快照、加密、backing file | ✅ 原生 | ✅ | ✅ | 本地/云导入首选（体积小） |
| **vhd/vpc** | Hyper-V 系；动态/固定两种 | ✅（动态） | ✅ | ✅ | 跨虚拟化平台 |
| **vmdk** | VMware 系；descriptor + extent 分离 | ✅ | ✅ | ✅ | 从 VMware 迁移 |
| **vdi/ova/…** | VirtualBox / OVF 打包 | — | — | ❌（需转换） | 先转换再导入 |

**选择建议**：自己产出与上传一律 **qcow2**（体积最小、云平台通用）；
从 `dd`/物理盘导出得到 raw，`qemu-img convert` 转 qcow2 再上传。

> **稀疏（sparse）**含义：只存实际写过的块。100 GiB 的空盘 qcow2 可能只有几百 MiB。
> 但"虚拟大小"仍是 100 GiB —— 云平台会按虚拟大小校验，别被文件体积误导（`qemu-img info` 两栏对比看）。

## 2. qemu-img 速查

```bash
qemu-img info disk.qcow2                 # virtual size / disk size / backing file / 加密
qemu-img info --output=json disk.qcow2   # 脚本友好

# 转换（-p 显示进度；-c 压缩 qcow2）
qemu-img convert -p -f raw   -O qcow2 disk.raw  disk.qcow2
qemu-img convert -p -f qcow2 -O raw   disk.qcow2 disk.raw     # 反向（导入时云平台常要 raw/vhd）

# 从物理盘/分区直接导出
qemu-img convert -p -f raw -O qcow2 /dev/sda out.qcow2

# 一致性检查与修复（导入前必做，尤其是 dd 或在线抓取的镜像）
qemu-img check disk.qcow2

# 调整虚拟大小（谨慎：只改元数据，不扩文件系统）
qemu-img resize disk.qcow2 +10G
```

> 只需**改镜像内部文件**（改 fstab、装包）时，不要用 `qemu-img resize` 或启动虚拟机，
> 用 §4 的离线手段。

## 3. 本地起虚拟机验证（导入前必跑）

```bash
# ① virtio-blk + Legacy（SeaBIOS，默认）
qemu-system-x86_64 -enable-kvm -m 4096 -smp 4 \
  -drive file=disk.qcow2,if=virtio,format=qcow2 \
  -netdev user,id=n0 -device virtio-net-pci,netdev=n0 \
  -nographic -append 'console=ttyS0'

# ② virtio-blk + UEFI（OVMF）
qemu-system-x86_64 -enable-kvm -m 4096 \
  -drive if=pflash,format=raw,readonly=on,file=/usr/share/OVMF/OVMF_CODE.fd \
  -drive if=pflash,format=raw,file=./OVMF_VARS.fd \
  -drive file=disk.qcow2,if=virtio,format=qcow2 -nographic

# ③ virtio-scsi + UEFI（华为场景）
qemu-system-x86_64 -enable-kvm -m 4096 -bios /usr/share/OVMF/OVMF.fd \
  -device virtio-scsi-pci,id=scsi0 \
  -drive if=none,id=d0,file=disk.qcow2,format=qcow2 -device scsi-hd,drive=d0,bus=scsi0.0 \
  -nographic

# ④ NVMe + UEFI（阿里新规格场景）
qemu-system-x86_64 -enable-kvm -m 4096 -bios /usr/share/OVMF/OVMF.fd \
  -drive if=none,id=d0,file=disk.qcow2,format=qcow2 -device nvme,drive=d0,serial=img01 \
  -nographic
```

**每次确认四项**：能引导到登录、网卡拿到 IP、`cloud-init status` 为 `done`、`/sys/firmware/efi` 有无与预期一致。

> OVMF 包名：RHEL/CentOS `edk2-ovmf`；Debian/Ubuntu `ovmf`；路径可能是 `/usr/share/OVMF/OVMF.fd`
> 或 `/usr/share/edk2/ovmf/OVMF_CODE.fd`（`rpm -ql edk2-ovmf | grep -i fd` 查）。

## 4. 离线处理三套手段

### 4.1 qemu-nbd：把镜像当块设备挂载（手工、最灵活）

```bash
modprobe nbd max_part=16
qemu-nbd -c /dev/nbd0 disk.qcow2
lsblk /dev/nbd0                      # 看到 nbd0p1/p2/p3
mount /dev/nbd0p3 /mnt               # 挂根分区
# ... 改文件、chroot、重建 initramfs ...
umount /mnt
qemu-nbd -d /dev/nbd0
```

### 4.2 libguestfs：不挂载内核、直接读改（安全、脚本友好）

```bash
virt-cat   -a disk.qcow2 /etc/fstab          # 看文件
virt-edit  -a disk.qcow2 /etc/fstab          # 改文件
virt-ls    -a disk.qcow2 /boot/efi/EFI/BOOT/ # 列目录
virt-copy-in  -a disk.qcow2 script.sh /root/ # 塞文件
virt-copy-out -a disk.qcow2 /etc /tmp/out/   # 取文件
guestfish -a disk.qcow2 -i                   # 交互式 shell
```

> libguestfs 用的是一个自带的极简内核（不用宿主内核），所以**不会因为镜像里的驱动/分区问题失败**，
> 比手动 `mount -o loop` 稳。这是排查"起不来的镜像"的首选工具。

### 4.3 virt-customize：批量改造（产线主力）

```bash
virt-customize -a disk.qcow2 \
  --run-command 'dracut -f --add-drivers "virtio_blk virtio_scsi virtio_net virtio_console nvme nvme_core xfs"' \
  --run-command 'printf "add_drivers+=\" virtio_blk virtio_scsi nvme\"\n" > /etc/dracut.conf.d/virtio.conf' \
  --run-command 'bash /root/check-image.sh --strict' \
  --install cloud-init,qemu-guest-agent \
  --selinux-relabel
```

常用开关：
| 开关 | 用途 |
|---|---|
| `--install` / `--uninstall` | 装/卸包（需 guest 内包管理器可用） |
| `--run-command` / `--run` | 执行命令/脚本（`--run` 会把宿主机脚本拷进去执行） |
| `--copy-in` | 拷文件进镜像 |
| `--edit` / `--write` | 改/写单个文件 |
| `--truncate` | 清空文件（清日志/状态用） |
| `--selinux-relabel` | 改动后重打 SELinux 标签（enforcing 时必须） |
| `--no-network` | 禁止镜像内联网（隔离环境） |

> 顺序提示：**先在镜像内跑自检脚本拿到 PASS，再上传导入**——把检查放在 `virt-customize` 的最后一步，
> 输出直接落进构建日志（见 `projects/kvm-image-check/README.md` 的 CI 集成示例）。

### 4.4 virt-sysprep：标准化"出厂清理"

```bash
virt-sysprep -a disk.qcow2 --operations defaults,-ssh-userdir
# 或明确列出要做的操作
virt-sysprep -a disk.qcow2 --enable machine-id,ssh-hostkeys,logfiles,bash-history
```

它与 [[entities/公有云镜像 制作 与 导入 实战]] §1 的手工清理清单是同一件事：
`machine-id`、`ssh-hostkeys`、`logfiles`、`bash-history`、`net-hostname`、`udev-persistent-net` 等。
**产线建议**：用手工清单建立理解，用 `virt-sysprep` 收敛为可重复的一步。

## 5. 常见坑

| 现象 | 原因 | 处置 |
|---|---|---|
| `qemu-nbd: Could not open '/dev/nbd0'` | nbd 模块没加载 | `modprobe nbd max_part=16` |
| 挂载后改的文件"没生效" | 镜像被 QEMU 占用（有写锁） | 先关掉虚拟机；必要时 `qemu-img info` 看是否被锁 |
| 改完起不来看不到设备 | SELinux 标签不对 | `virt-customize --selinux-relabel` 或 guest 内 `touch /.autorelabel` |
| libguestfs 报"无法识别文件系统" | 镜像损坏或多段/加密 | `qemu-img check`；加密镜像需密钥 |
| 导入后被平台拒绝 | 格式/虚拟大小/架构不符 | 见 [[concepts/云平台 镜像 与 云盘 产品语义]] §5.1 |
| 转换后体积暴涨 | raw 无稀疏 | 转 qcow2 或用 `-S 4k` 保持稀疏 |
| 云上 `df` 不随系统盘变大 | 只做了 host 侧扩容 | 见 [[concepts/磁盘分区 文件系统 与 挂载管理]] §4 |

## 6. 与自检脚本的配合（推荐工作流）

```
① 装好/导出镜像（raw/qcow2）
② qemu-img check            ← 结构完整性
③ virt-customize 改造 + 清理（§4.3 / §4.4）
④ check-image.sh --root /mnt/imgroot --strict   ← 规范与驱动自检
⑤ qemu 本地四种挂法各起一次（§3）
⑥ 转 qcow2 上传 OSS/OBS/COS 并导入
⑦ 创建实例做云上验收（[[concepts/KVM 公有云 镜像 适配]] §12.2）
```
