# Claude 提示词工程最佳实践指南

> Claude 是由 [[entities/anthropic|Anthropic]] 开发的 AI 助手系列模型。

> 基于 Anthropic 官方文档整理，适用于 Claude 所有模型（Sonnet / Opus / Haiku / Fable）

---

## 一、核心原则

### 1. 清晰直接，详细具体

Claude 对细节敏感的模型，提示词越清晰，输出越准确。

| 做法 | ❌ 模糊 | ✅ 清晰 |
|------|---------|---------|
| **明确任务** | "帮我写段代码" | "用 Python 写一个函数，输入是 URL 列表，输出是每个 URL 的 HTTP 状态码和响应时间" |
| **指定格式** | "给我几个方案" | "给我 3 个方案，每个方案用一段话描述，然后列出优缺点对比表" |
| **限定范围** | "分析这段代码" | "分析这段代码的性能瓶颈，重点关注循环嵌套和数据库查询次数" |

### 2. 给 Claude 分配角色

设定角色让 Claude 进入特定"思维模式"，输出质量显著提升。

```
你是一名资深数据库协议逆向工程师。你需要分析以下 pcap 抓包数据，
识别 MySQL 协议的握手包结构，输出字段级协议格式文档。
```

```
你是一名前端架构师，对 Ant Design 5.x 有深入理解。
请审查以下组件的 UI5.0 规范符合度。
```

### 3. 提供示例（Few-Shot）

给出输入/输出示例，Claude 能快速理解你的期望格式。

```
将以下 SQL 查询转换为自然语言描述：

输入：SELECT * FROM users WHERE age > 18
输出：查询所有年龄大于 18 岁的用户

输入：INSERT INTO orders (user_id, amount) VALUES (1, 99.9)
输出：插入一条用户 ID 为 1、金额为 99.9 的订单

输入：DELETE FROM sessions WHERE expired_at < NOW()
输出：
```

### 4. 结构化输出

要求 Claude 以特定格式输出，方便后续处理。

```
请分析这段代码的安全性，以 JSON 格式输出：
{
  "issues": [
    {"severity": "high|medium|low", "line": 42, "description": "...", "suggestion": "..."}
  ],
  "summary": "总体评价"
}
```

## 二、进阶技巧

### 5. 拆解复杂任务（Chain-of-Thought）

对于复杂任务，让 Claude 先列出思考步骤再输出，大幅提升准确性。

```
逐步思考：
1. 首先识别输入数据中的表名和字段
2. 然后分析 WHERE 条件中的关系运算
3. 最后将结果组合为完整的 SQL 语句

请按上述步骤分析以下查询：...
```

### 6. 链式提示（Chain Complex Prompts）

将一个大任务拆成多个小步骤，每一步的输出作为下一步的输入。

```
步骤 1：从以下 pcap 文件中提取所有 TCP 会话
步骤 2：识别每个会话的应用层协议
步骤 3：对 HTTP 会话，提取 Method、URI、Status Code
步骤 4：生成协议分析报告
```

### 7. 指定输出长度和风格

控制输出的详细程度和语气。

- "用 3 句话概括"
- "输出不超过 500 字"
- "用技术文档的风格"
- "写给非技术人员看"

### 8. 使用 XML 标签组织复杂提示

对于包含多部分内容的提示，用 XML 标签帮助 Claude 解析结构。

```
<context>
  我们正在开发一个数据库协议解码器，支持 Elasticsearch HTTP 协议。
</context>

<task>
  请为以下 API 端点生成 actionType 映射规则
</task>

<api_list>
  GET /{index}/_search
  PUT /{index}/_doc/{id}
  POST /_bulk
  DELETE /{index}
</api_list>

<output_format>
  表格形式，包含：HTTP Method、URI Pattern、actionType、说明
</output_format>
```

### 9. 告知 Claude"不确定时怎么说"

让 Claude 在不确定时明确表达，而不是编造答案。

```
如果你对某个协议字段的位宽或字节序不确定，请明确标注 "[需要确认]"
而不是猜测一个值。你的回答将用于生产环境解码器生成，准确性至关重要。
```

## 三、Claude Code 专用技巧

### 10. 利用 CLAUDE.md 设定项目级规则

在项目根目录创建 `CLAUDE.md`，让 Claude 永远知道项目的上下文。

```markdown
# 项目规则

## 技术栈
- 前端：React 18 + Ant Design 5.x + TypeScript
- 后端：Python 3.11 + FastAPI
- 数据库：PostgreSQL 15

## 编码规范
- 使用 ESLint + Prettier
- 组件文件使用 PascalCase 命名
- API 路由使用 kebab-case

## 约束
- 不要引入新的 UI 组件库
- 所有对外 API 必须有类型定义
- 测试覆盖率不低于 80%
```

### 11. 使用 Tools / Skills

对于重复性任务，创建 Skill 固化流程。Skill 本质上是可复用的提示词模板和工作流定义系统。

```yaml
# Skill 示例
name: db-decoder-creator
description: 创建数据库协议解码器
steps:
  1. 分析 pcap 抓包文件
  2. 识别协议结构和消息格式
  3. 生成 C++ 解码器代码
  4. 编译验证
```

### 12. 指定工具使用

明确告诉 Claude 使用哪些工具。

```
使用 Read 工具读取 src/config.py，然后用 Grep 搜索所有使用
DATABASE_URL 的地方，最后用 Edit 工具修改连接池配置。
```

## 四、常见误区

| 误区          | 说明            | 正确做法                |
| ----------- | ------------- | ------------------- |
| **提示词越短越好** | 过短的提示缺乏上下文    | 提供足够的背景和约束          |
| **一次性完成**   | 复杂任务期望一次就完美   | 分步骤迭代，逐步优化          |
| **忽略格式约束**  | 不指定输出格式       | 明确要求 JSON/表格/代码块等   |
| **过于抽象的指令** | "优化一下"太模糊     | "将循环改为列表推导式，减少中间变量" |
| **不处理不确定性** | Claude 可能编造答案 | 告诉 Claude"不确定就说不知道" |

## 五、提示词模板速查

### 代码审查模板

```
作为一个 [角色]，请审查以下 [类型] 代码。

需要关注的重点：
1. [维度 1]
2. [维度 2]
3. [维度 3]

代码：
```
[代码内容]
```

请以 [格式] 输出审查结果。
```

### 文档生成模板

```
请为 [主题] 编写一份 [类型] 文档。

目标读者：[受众描述]
包含内容：
1. [章节 1]
2. [章节 2]
3. [章节 3]

风格要求：[正式/轻松/技术]
篇幅要求：[页数/字数]
```

### 调试/排错模板

```
我在 [环境] 中遇到了以下问题：

问题描述：[具体现象]
期望行为：[应该怎样]
实际行为：[实际怎样]

相关代码：
```
[代码片段]
```

已经尝试过：
1. [已尝试的方法 1]
2. [已尝试的方法 2]

请帮我诊断问题原因并给出解决方案。
```

## 六、总结

| 原则         | 一句话              |
| ---------- | ---------------- |
| **清晰具体**   | 多说细节，少说模糊词       |
| **角色设定**   | 告诉 Claude"你是谁"   |
| **提供示例**   | 输入输出样例最有效        |
| **结构化输出**  | 要求 JSON/表格/列表    |
| **拆解步骤**   | 复杂任务分步走          |
| **链式提示**   | 上一步输出是下一步输入      |
| **XML 标签** | 多段内容用标签包裹        |
| **处理不确定性** | 允许 Claude 说"不知道" |
| **项目级配置**  | CLAUDE.md 设定全局规则 |
| **迭代优化**   | 好提示词是改出来的        |

> 核心信条：**把 Claude 当成一个聪明但需要明确指令的新同事——告诉他背景、告诉他怎么做、告诉他期望的格式，剩下的交给模型。**
