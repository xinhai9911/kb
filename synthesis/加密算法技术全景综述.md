# 加密算法技术全景综述

> 汇总本批加密深挖：原理概念（concepts/）+ 工程实战（entities/）。
> 起点 [[concepts/加密算法总览与分类]]。

## 1. 全景地图

```
                    ┌─────────────────────────────┐
   机密性 ─────────►│  对称加密  AES / ChaCha20   │── 批量数据
                    └──────────────┬──────────────┘
                                   │ 密钥分发难
                    ┌──────────────┴──────────────┐
   认证+密钥协商 ──►│ 非对称  RSA / ECC / ECDHE   │── 少量数据
                    └──────────────┬──────────────┘
                                   │
   完整性 ─────────►┌──────────────┴──────────────┐
                    │ 哈希/MAC  SHA / HMAC / SM3  │
                    └──────────────┬──────────────┘
                                   │
                    ┌──────────────┴──────────────┐
   编排成协议 ─────►│  TLS 1.3  握手 + 记录层     │
                    └──────────────┬──────────────┘
                                   │
        ┌──────────────────────────┼──────────────────────────┐
        ▼                          ▼                          ▼
  硬件加速(AES-NI/      侧信道/常量时间          合规(国密 SM2/3/4,
  offload/HSM)          (实现安全)              TLCP/PKI 证书)
```

## 2. 核心结论

1. **混合模式是铁律**：非对称只做「协商+认证」，对称扛「批量加密」。纯非对称批量不可行。
2. **AEAD 是唯一可接受的对称用法**：GCM / ChaCha20-Poly1305，绝不手搓 encrypt+MAC。
3. **PFS 是 TLS 底线**：ECDHE 强制，RSA 密钥传输已淘汰（TLS 1.3 移除）。
4. **实现安全 = 算法安全**：侧信道（时序/缓存）靠常量时间 + 硬件指令（AES-NI）规避。
5. **性能靠卸载**：AES-NI / kTLS / SmartNIC 让 TLS 逼近线速。
6. **合规驱动国密**：政务金融用 SM2/3/4 + TLCP（双证书），与标准 TLS 栈不互通需双栈。

## 3. 选型速查

| 需求 | 推荐 |
|------|------|
| 对称加密 | AES-256-GCM；无 AES-NI 设备用 ChaCha20-Poly1305 |
| 密钥交换 | X25519 (ECDHE)，强制 PFS |
| 签名/证书 | ECDSA P-256 或 Ed25519（新系统优先 Ed25519） |
| 哈希 | SHA-256（SHA-1/MD5 退役） |
| MAC | HMAC-SHA256 |
| 协议 | TLS 1.3 仅 |
| 国密合规 | SM2/SM3/SM4 + TLCP + 国密库（GmSSL/BabaSSL） |
| 密钥保护 | HSM/TPM 存私钥，主机只持有句柄 |
