## 2. 核心结论

1. **从小写对，再谈架构**：坏代码会放大高层复杂度（原则→模式→重构）。
2. **微服务不是默认**：<3 团队先用模块化单体，按真实痛点拆（[[concepts/架构风格演进]]）。
3. **分布式必付代价**：CAP、幂等、最终一致、Saga 是绕不开的（[[concepts/分布式系统基础]]）。
4. **可观测是前提**：没 trace/指标/日志，微服务就是黑盒（[[concepts/可观测性工程]]）。
5. **韧性靠组合拳**：限流+舱壁+超时+退避重试+熔断+降级（[[concepts/韧性设计]]）。
6. **发布要安全**：小步、自动化、金丝雀、秒级回滚、特性开关（[[concepts/CI_CD与测试策略]]）。
7. **一切是权衡**：每个方案说得出放弃了什么（[[concepts/系统设计思维]]）。

## 5. 学习路径

1. 原则 → 模式 → 重构（写好代码）
2. 架构风格 → DDD → 微服务拆分（切对边界）
3. 分布式基础（接受分布式的代价）
4. 可观测 + 韧性（让系统稳）
5. CI/CD + 测试（可靠交付）
6. API 设计（对外的契约）
7. 系统设计思维（用 trade-off 串起一切）
