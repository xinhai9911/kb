# 容器分布式技术全景综述（Container & Distributed Systems）

> 本文是**入口与地图**，不是细节。按图索骥：每个话题点进去看对应笔记。
> 先建立全局，再深入局部——这是学习「容器分布式」最快的路径。

---

## 1. 一句话定位

**容器分布式 = 把「容器」作为最小交付与调度单元，运行在一组由共识协议协调、跨网络互联的机器集群上。**

- 「**容器**」解决：应用如何被干净、可复现、轻量地打包与运行（单机上）。
- 「**分布式**」解决：一群容器跑在一堆机器上时的调度、网络、存储、自愈、一致性。
- 把两者缝合起来的，是**编排层（Kubernetes）**——用声明式 API + 控制循环，把数据中心当一台电脑编程（见 [[synthesis/Kubernetes 技术全景综述]]）。

---

## 2. 知识地图（分层全景）

```
┌─────────────────────────────────────────────────────────────┐
│  分布式支柱（跨节点协作）                                       │
│   网络 CNI/Cilium │ 存储 PV/PVC │ 一致性 etcd/Raft             │
│   韧性(超时/重试/熔断) │ 可观测(日志/指标/追踪)                  │
├─────────────────────────────────────────────────────────────┤
│  编排层 Kubernetes（声明式 + 控制循环 + API 为中心 + 自愈）       │
│   控制面: apiserver/etcd/scheduler/controller-manager         │
│   数据面: kubelet/kube-proxy/CRI/CNI/CSI                       │
├─────────────────────────────────────────────────────────────┤
│  安全层（贯穿上下）                                            │
│   Capabilities │ seccomp │ AppArmor/SELinux │ Rootless        │
│   镜像供应链 SBOM/签名 │ PodSecurity │ Falco 运行时检测          │
├─────────────────────────────────────────────────────────────┤
│  容器运行时（从命令到内核）                                     │
│   docker/podman → containerd/CRI-O → runc → clone/setns/cgroup │
├─────────────────────────────────────────────────────────────┤
│  镜像（OCI Image Spec）                                        │
│   manifest + config + layers（分层 + Copy-on-Write + 内容寻址） │
├─────────────────────────────────────────────────────────────┤
│  内核基石（容器的物理事实）                                     │
│   Namespace(隔离视野) │ Cgroups(限制用量) │ OverlayFS(分层存储) │
└─────────────────────────────────────────────────────────────┘
```

> 越往下越「硬」——内核基石决定了容器的本质；越往上越「软」——编排与安全是工程约定。
> 学反了（先背 K8s 命令、不懂容器是什么）最容易踩坑。

## 4. 常见误区（避坑）

| 误区 | 真相 |
|---|---|
| 容器是轻量虚拟机 | 否，共享内核、只是受限进程（[[concepts/容器原理与运行时#0. 一句话定位]]） |
| Namespace 是安全边界 | 否，它是隔离不是防护；安全靠 Capabilities/seccomp/MAC（[[concepts/容器安全#2. 内核隔离的局限与真正边界]]） |
| K8s 里还在用 docker | 1.20+ 移除 dockershim，经 CRI 调 containerd/CRI-O（[[entities/容器实战#5. 从 docker 到 K8s 的心智切换]]） |
| 镜像越小越好 | 小是手段，还得有 SBOM + 签名溯源，否则「小且不可信」（[[concepts/容器安全#7. 镜像供应链安全]]） |
| 分布式 = 加机器 | 加机器引入分区/一致/脑裂，要先懂 CAP/共识（[[concepts/分布式系统基础]]） |
| rootless 万能 | 有功能限制，需评估；但能大幅降逃逸危害（[[concepts/容器安全#6. Rootless 与 User Namespace]]） |

## 7. 一句话收尾

> 容器是「被关在内核小世界里的普通进程」；分布式编排是「让这群小世界跨机器协同的 declarative 操作系统」。
> 先把**单容器**想透（L0~L4），再进**编排与分布式**（L5~L6），全程用安全思维贯穿——这就是容器分布式的全貌。
