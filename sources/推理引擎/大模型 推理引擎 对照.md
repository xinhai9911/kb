# 哪些大模型在用 vLLM / SGLang

> [!warning] 重要前提：这不是"非此即彼"的划分
> vLLM 与 SGLang 都是**通用 LLM 推理引擎**，几乎所有主流模型家族（Llama、Qwen、DeepSeek、Mistral、GLM 等）都**同时被两家支持**。实践中"某模型用 vLLM 还是 SGLang"取决于部署方选择，而非模型本身的绑定。
> 因此下面按"官方推荐 / 社区默认 / 通用支持"三档来对照，比简单二分更准确。

## 一、唯一明确的官方背书：DeepSeek → SGLang

| 模型 | 官方推荐引擎 | 依据 |
|------|--------------|------|
| **DeepSeek-V2 / V3 / R1** | **SGLang（推荐）** | DeepSeek 官方仓库 README 明确写 "Inference with SGLang (recommended)"；SGLang 团队与 DeepSeek 深度协同，针对 MLA、FP8(W8A8)、FP8 KV Cache、CUDA Graph、Torch Compile 做了专门优化，开源框架中性能最佳 |
| DeepSeek 系列（备选） | vLLM / LMDeploy / TensorRT-LLM | 官方同样列出 vLLM 等作为可选部署路径，但 SGLang 被标为推荐 |

> 这是当前公开信息中**最强、最明确的"模型↔引擎"绑定信号**：DeepSeek 自身的 API/开源推理栈以 SGLang 为核心。

## 二、通用支持（两家都行，看部署方）

下列模型家族在 vLLM 和 SGLang 中**均可部署**，不存在官方排他：

| 模型家族 | vLLM 支持 | SGLang 支持 | 备注 |
|----------|:---------:|:-----------:|------|
| **Llama / Llama-2 / Llama-3 系列** | ✅ 示例命令见 `entities/vllm.md` | ✅ 示例命令见 `entities/sglang.md` | vault 中两家都拿 Llama-3 做示例 |
| **Qwen / Qwen2 / Qwen3 系列** | ✅ | ✅ | Qwen 官方部署文档同时列出 SGLang、vLLM、TGI；Qwen 自研架构变体在两家都需特定解析 |
| **Mistral / Mixtral（MoE）** | ✅ | ✅ | MoE 专家并行两家均支持 |
| **DeepSeek 系列** | ✅（备选） | ✅（官方推荐） | 见上节 |
| **GLM / ChatGLM 系列** | ✅ | ✅ | 智谱开源模型两家通用 |

## 三、vLLM 的整体定位（来自 vault）

- `concepts/LLM 推理 优化.md`：**"vLLM 是目前部署最广的开源推理引擎"**。
- 适用场景（见 `推理 引擎 选择.md`）：高并发 API 服务、通用生产部署、与 HuggingFace 生态无缝集成。
- 因此**绝大多数自部署项目、私有化部署、第三方平台默认走 vLLM**，但这不等于"某个模型只属于 vLLM"——只是 vLLM 的市场覆盖面最广。

## 四、SGLang 的整体定位（来自 vault + 公开信息）

- vault `entities/sglang.md`：核心创新 RadixAttention、结构化生成、分裂式 Prefill-Decode，最佳场景为 Agent / 多轮对话 / 结构化输出。
- 公开信息补充：**与 DeepSeek 的强绑定**是 SGLang 最显著的"模型↔引擎"信号；在长上下文、多轮、复杂控制流场景上社区偏好 SGLang。

## 五、结论速查

| 你想知道 | 答案 |
|----------|------|
| 哪个模型"官方指定"用 SGLang？ | **DeepSeek（V2/V3/R1）**——官方推荐 |
| 哪个引擎覆盖模型最多、部署最广？ | **vLLM**（通用生产部署首选，见 vault 原文） |
| Llama / Qwen / Mistral / GLM 用哪个？ | **两家都支持**，取决于你的部署选择 |
| 能用一张表"X 只 vLLM / Y 只 SGLang"吗？ | **不能**——现实是高度重叠，仅 DeepSeek↔SGLang 有官方强信号 |
